# 终局地面覆盖层样板

本批只提供两个稳定资产 ID：`state_down` 与 `state_dead`。它们是人物下方的透明地面效果，不含角色、装备或可决定战斗结果的信息。显示逻辑应读取规则结果：暂时失能只显示 `state_down`；确认死亡之后才切换 `state_dead`。倒地人物自身的脸、衣甲、武器和整体倒伏姿态继续由主工程组合，保持同一身份；本批尚未完成该组合。

| 文件 | 表现 | 原始 RGBA SHA-256 |
| --- | --- | --- |
| `state_down.png` | 扁平接触阴影、少量土尘；可幸存 | `18d62d90471e84b2f220e469101c90e7699e7ca620a455d2a2b475ea363c7b7a` |
| `state_dead.png` | 同一落点的终局阴影、少量暗红血迹 | `b68ee3b295273ad9b2397fb32ead5efa43dc4d543e5eddf8096e52a2de7047aa` |

两个文件均为 `1254×1254` 原始透明 PNG。`assets.fragment.json` 给出 Godot `asset_document` 字段样例：整图裁取、逻辑尺寸 90×90、枢轴 `(0.5, 0.70)` 对齐棋格原点、层高 `-10` 以置于人物下面。数值仅为第一轮对位，主代理须在完整倒伏组合中校准。片段使用本机绝对路径便于当前工程导入；发布时由工作台复制到工程 `images/` 并改为项目内路径。不自动替换当前 `current.asset.json` 或发布资源。

查看方式：打开 `qa-preview.png`，每行分别为倒地与确认死亡，每行展示草绿/浅土底色上的 90px 与 180px 整图缩放。运行 `python qa_preview.py` 可重建预览和 `qa-report.json`。这项检查确认真实 RGBA 透明通道、无整片不透明底色、两层同向扁平轮廓及正常尺寸大致可辨。生成时目视检查了原始图：无第二个人物、脸、手、装备或血腥解剖物。

已验证范围：独立图像的浅土与深绿背景、90px 与 180px 缩放，以及 alpha 像素边界。两张原图的可见主轮廓集中于画布下半部，边缘保留较淡半透明像素。深绿色地块上的 90px 死亡血迹辨识偏弱，需要结合规则状态提示、人物倒姿和结果反馈判断；此层单独不应承担死亡语义。未在 Godot 实际棋盘与同一角色倒姿叠放，也未验证加速、跳过、音效或角色身份连续性；主代理集成后仍需做这些验证。PNG 没有可编辑图层文件，完整提示和生成源路径见 `prompts.md`，发布导出宜保留 RGBA、原始母图和上述逻辑尺寸记录。

资源成本：新增约两张 1254 方图的纹理与图集管理；同屏大量尸体时可在集成阶段统一缩小或图集化。它们不依赖特定地面颜色，但沙土上对比更明显，深色地块需进一步实测。
