# 最小原型的半身棋子样板

2026-09-19。此文件描述本轮实际程序图形及其边界，不代表最终商业美术品质。对应源文件：`game/presentation/battle_board.gd`。

## 本轮采用的方向

采用有脸、头盔或兜帽、肩甲、持械手与武器的半身棋子，下接清楚的椭圆底座。友军蓝绿、敌军锈红，行动标记用象牙金；底座颜色与生命／护甲条提供第二层辨识。七类轮廓覆盖盾卫、长枪手、弓手、猎人、游击者、劫掠者与战犬。战犬保留身躯、尖耳、吻部、四肢暗示、尾巴和队伍披挂。

当前行动者使用两层椭圆底环、左右菱形角标、头顶下指箭头，以及“姓名 · 岗位”标签。标记在深度排序后的前景层绘制，前排棋子、物件和攻击动画不会遮住它；底环、箭头和标签都读取同一移动插值点，移动时一起跟随。形状、文字和象牙金共同表达回合归属，避免只靠颜色。

战场本体为全视口草土底色、稀疏草丛笔触与磨损土路，网格以低对比边线压在环境之上；它们只营造边境气氛，不表示未实现地形规则。棋盘依据主界面传入的安全矩形重新缩放，格子、半身角色、武器高点和底座均留在 HUD 外。油渍弧纹、水面线纹、分层火苗和半透明蒸汽继续只读取真实单元格状态；油桶、水桶、木障碍与粮仓通过形状区分。

| 方案 | 收益 | 限制与成本 |
| --- | --- | --- |
| 本轮半身棋子 | 正常缩放时脸和武器更清楚；少量动作就能展示攻击、受击与移动；较易统一装备轮廓 | 缺少完整脚步与身体动作；前后排可能遮挡；需要用底座表达精确格位 |
| 原计划全身角色 | 跑动、翻滚、姿态与受力更自然，可扩展更丰富的演出 | 增加动作、方向、装备层适配和锚点工作；同视野下脸和武器细节更小 |

本轮按用户授权使用半身样板验证；不同时维护第二套全身素材线。最终是否延续半身仍应根据真实试玩与样板审美决定，不能把节省原型成本视为已确认的长期画风。

## 实际接口与行为

- `set_battle(state)` 保存深拷贝展示快照，不改变战斗状态；`set_selected(id)` 与 `set_preview(info)` 更新选中和悬停预览。
- `set_action_overlay(info)` 接受主流程已经计算的 `{range_cells, blocked_cells, valid_targets, action_name, action_id}`；三个格数组均为 `{q,r}`。棋盘不从技能距离、掩体、蒸汽或单位状态反推这些集合，也不把点击结果写回规则。
- `set_playfield_rect(rect:Rect2)` 接收棋盘 Control 本地坐标的安全区。背景仍铺满整个 Control；逻辑地图只缩放至该矩形内，默认未传时保留带边距的完整可读战场。`cell_screen_position(q,r)` 返回同一变换下的本地锚点，可用于界面提示框。
- `cell_clicked(q,r)` 只发送有效格坐标；`cell_hovered(q,r)` 离开地图时发送 `(-1,-1)`，外围界面清除悬停预览但保留当前技能范围。`unit_hovered(unit_id)` 在其前发送；鼠标命中角色可见的头盔／头部、躯干或底座均回报该角色所属格，移到同一格地面时发送空 ID。命中按前景绘制次序反向检查，采用椭圆头部、收腰躯干和底座轮廓，不让武器周围的透明矩形抢走空格点击。
- `play_events(events,speed)` 排队展示位移、攻击前冲、命中震动、伤害／闪避／状态浮字与元素扩散环。移动优先读事件的 `from_q/from_r`，缺省时使用前一展示快照。
- `set_animation_speed(speed)` 设置全局倍率，`play_events` 的 `speed` 是额外批次倍率；全局倍率为 0 时清空表现队列并立即呈现当前规则快照。跳过不推进回合，不增减伤害或资源。
- 逻辑网格保留 9×7 轴向坐标，但不再缩放已退役的标题／页脚卡片。项目窗口最小尺寸为 1180×740，棋盘 Control 自身不强加最小尺寸；在该尺寸下，主流程以顶部约 64 像素至底部 HUD 上缘传入安全区。外围 HUD 与 tooltip 由主 AI 管理。
- 上条生命、下条护甲；当前行动者有双环、角标、箭头与岗位标签，选中者显示行动点。危险和物件预览读取 `affected`，路径读取 `path`，均为 `{q,r}` 数组。
- 移动可达格是蓝绿色半透明底和中心圆点；攻击射程是金色半透明底和菱形；被遮挡格是灰紫底与叉；合法目标是锈红准星；合法悬停的实际波及是紫色边框。单位/物件攻击的大准星画在前景；油/火/水全部可投掷中心改为地面半透明小准星，仅当前合法瞄准中心画前景大准星，避免遮盖棋子。状态不用泛用感叹号：戒备用小盾、破绽用裂盾、标记用准星、牵制用锁链；仅悬停时按真实格状态给出“脚下是火！”或按真实 `defending` 状态给出“守住阵线”。这些是已有规则输出，没有新增士气或心理数值。

`tactical_glyph.gd` 是可交给底栏复用的原创程序图标 Control，接受 `glyph`、`tint` 与 `set_glyph(id)`。当前轮廓覆盖 `move`、`attack`、`shield_bash`、`push`、`defend`、`oil`、`fire`、`water`、`mark`、`command_follow`、`command_pin`、`command_recall`（兼容 `pin`、`recall`）、`guard`、`spear`、`archer`、`hunter`、`dog`、`skirmisher`、`raider`。图标只说明行动或岗位类型，不携带伤害、资源或命中判断。

## 来源与素材记录

所有人物、底座、物件、地图装饰、行动／射程叠层、元素效果与 `tactical_glyph.gd` 图标均为本项目原创程序绘图，由 AI 编写 Godot 绘制代码。本轮未下载或导入 Battle Brothers、PTR、参考图人物、第三方精灵或其他游戏资产；参考图只作为用户表达风格的依据。没有调用图像生成工具。

字体使用运行时 `SystemFont`，优先 Microsoft YaHei / Microsoft YaHei UI，缺失时尝试 Noto Sans CJK SC / Arial。本轮不把系统字体文件打进游戏；目标 Windows 设备的中文显示仍需导出包检查。源素材就是 `battle_board.gd` 与 `tactical_glyph.gd` 的图形定义，无额外贴图、骨骼文件或授权素材。导出时随 Godot 项目编译这两个脚本；不生成或另存难维护的位图副本。

正式美术需要另行建立经过用户评审的配色、面部、装备层、锚点、朝向、动作时间与图标规范；程序占位可完整替换，保持规则接口不变。

## 验证证据与已知限制

初始视图通过 Godot 4.7.2 脚本解析检查。2026-09-18 已完成主界面集成，并从 Windows 导出包生成界面截图：中文字体、棋盘点击、可达格、粮仓目标、正常／加速／跳过不改规则及小窗口布局已有自动验证与截图复核。实际证据见 `docs/08-validation.md` 和 `docs/09-visual-review.md`。这些结果仍不构成真人逐帧动画观感或商业美术验收。

0.1.2 专项角色先完成 Godot 4.7.2 headless 解析；主 AI 再接入全视口 HUD。图标保持调用方的 27/40 像素尺寸，猎人的跟随/牵制/撤回分别使用对应原创图示。底部动作和岗位、上方摘要、只读详情分别独立于规则状态。

本轮实际导出与截图结论以 [08-validation.md](08-validation.md)、[09-visual-review.md](09-visual-review.md) 为准。新增验收覆盖整个视口、底栏高度、密集人物轮廓、小窗口猎人完整招式、长状态卡、日志展开和不穿透点击。正常/加速/跳过继续只作用于表现。真人观感、正式方向与装备叠层仍待后续评审。

当前表现限制：尚无音频、完整骨骼、逐帧手绘、武器飞行物、逐个命中时刻的历史状态回放；展示使用结算后的规则快照，因此一次动作内多名死亡与多个串联移动主要用浮字、轨迹和日志解释。它是可玩机制的原创视觉占位，不是已经完成的商业美术样板。若批次演出难以理解，应由主 AI 扩展只读事件快照，不能让动画回调反向计算规则。

## 大地图程序样板（0.1.3）

对应源文件：`game/presentation/world_map.gd`。这是一个最小约 700×440、随容器等比缩放的只读 `Control`，为主界面的合同、旅行和营地面板预留地图画布；它不创建行程、不扣口粮，也不把点击当作出发。地图接收 `set_world(view: Dictionary)`，只读取 `locations`、`edges`、`location_id`、`route_path`、`visited_ids` 和 `travel_status`，忽略其余键；点击已发现地点仅发出 `location_selected(location_id)`，详情和任何旅行确认由主流程决定。

画面以旧羊皮纸、墨绿边地、程序河流、山脊、森林和磨损道路构成。河流、山林、纸面斑点与山线都只是原创程序装饰，没有地形、风险或可行走含义；实际可走区域只由规则输出的 `edges` 绘制。本次已走路段用青绿实线强调，当前已保存路线的未走部分用象牙金虚线强调，未走但已发现的路线为断续浅棕线。未发现地点仅显示问号与“未知地点”，不响应点击，也不伪装成可互动内容。已发现地点按营地、渡口、山脊、林边、粮仓、桥头绘制不同的小图案，名称和悬停说明来自只读地点数据；当前团旗从 `location_id` 定位，`route_path` 中的粮仓节点标注为“契约目的地”。

所有图形均为本项目原创 Godot `draw_*` 程序绘制，源素材即 `world_map.gd`，没有导入贴图、第三方素材、参考游戏资产或图像生成内容。中文字体沿用程序棋子样板的运行时系统字体顺序：Microsoft YaHei / Microsoft YaHei UI，回退 Noto Sans CJK SC / Arial；字体文件不随项目分发。导出时随项目脚本编译，维护时修改这一份矢量式源码即可，不生成难以追溯的位图副本。

该组件已接入主场景：地图展示、合同、逐站旅行、事件浏览、结算返营和营地生活共用规则状态。实际导出验证与正常/小窗口截图以 08-validation.md、09-visual-review.md 为准。它没有动画、声音、装备层或战斗动作：这些不属于大地图静态信息面的授权范围。
