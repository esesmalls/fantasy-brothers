# 最小原型的半身棋子样板

2026-09-18。此文件描述本轮实际程序图形及其边界，不代表最终商业美术品质。对应源文件：`game/presentation/battle_board.gd`。

## 本轮采用的方向

采用有脸、头盔或兜帽、肩甲、持械手与武器的半身棋子，下接清楚的椭圆底座。友军蓝绿、敌军锈红，行动标记用象牙金；底座颜色与生命／护甲条提供第二层辨识。七类轮廓覆盖盾卫、长枪手、弓手、猎人、游击者、劫掠者与战犬。战犬保留身躯、尖耳、吻部、四肢暗示、尾巴和队伍披挂。

当前行动者使用两层椭圆底环、左右菱形角标、头顶下指箭头，以及“姓名 · 岗位”标签。标记在深度排序后的前景层绘制，前排棋子、物件和攻击动画不会遮住它；底环、箭头和标签都读取同一移动插值点，移动时一起跟随。形状、文字和象牙金共同表达回合归属，避免只靠颜色。

场景采用暗色边境地图的线条与纹理：土色六边格、金属边线、油渍弧纹、水面线纹、分层火苗和半透明蒸汽。油桶、水桶、木障碍与粮仓通过形状区分。场景图形只表现规则中的状态，不增设不可交互的假按钮。

| 方案 | 收益 | 限制与成本 |
| --- | --- | --- |
| 本轮半身棋子 | 正常缩放时脸和武器更清楚；少量动作就能展示攻击、受击与移动；较易统一装备轮廓 | 缺少完整脚步与身体动作；前后排可能遮挡；需要用底座表达精确格位 |
| 原计划全身角色 | 跑动、翻滚、姿态与受力更自然，可扩展更丰富的演出 | 增加动作、方向、装备层适配和锚点工作；同视野下脸和武器细节更小 |

本轮按用户授权使用半身样板验证；不同时维护第二套全身素材线。最终是否延续半身仍应根据真实试玩与样板审美决定，不能把节省原型成本视为已确认的长期画风。

## 实际接口与行为

- `set_battle(state)` 保存深拷贝展示快照，不改变战斗状态；`set_selected(id)` 与 `set_preview(info)` 更新选中和悬停预览。
- `set_action_overlay(info)` 接受主流程已经计算的 `{range_cells, blocked_cells, valid_targets, action_name, action_id}`；三个格数组均为 `{q,r}`。棋盘不从技能距离、掩体、蒸汽或单位状态反推这些集合，也不把点击结果写回规则。
- `cell_clicked(q,r)` 只发送有效格坐标；`cell_hovered(q,r)` 离开地图时发送 `(-1,-1)`，外围界面清除悬停预览但保留当前技能范围。
- `play_events(events,speed)` 排队展示位移、攻击前冲、命中震动、伤害／闪避／状态浮字与元素扩散环。移动优先读事件的 `from_q/from_r`，缺省时使用前一展示快照。
- `set_animation_speed(speed)` 设置全局倍率，`play_events` 的 `speed` 是额外批次倍率；全局倍率为 0 时清空表现队列并立即呈现当前规则快照。跳过不推进回合，不增减伤害或资源。
- 逻辑画布 800×560，9×7 轴向六边格；Control 自动等比缩放并居中，鼠标坐标使用同样变换。外围 HUD 由主 AI 管理。
- 上条生命、下条护甲；当前行动者有双环、角标、箭头与岗位标签，选中者显示行动点。危险和物件预览读取 `affected`，路径读取 `path`，均为 `{q,r}` 数组。
- 移动可达格是蓝绿色半透明底和中心圆点；攻击射程是金色半透明底和菱形；被遮挡格是灰紫底与叉；合法目标是锈红准星；合法悬停的实际波及是紫色边框。图例用形状和文字补充颜色。单位/物件攻击的大准星画在前景；油/火/水全部可投掷中心改为地面半透明小准星，仅当前合法瞄准中心画前景大准星，避免遮盖棋子。

## 来源与素材记录

所有人物、底座、物件、地图装饰、行动／射程叠层与元素效果均为本项目原创程序绘图，由 AI 编写 Godot 绘制代码。本轮未下载或导入 Battle Brothers、PTR、参考图人物、第三方精灵或其他游戏资产；参考图只作为用户表达风格的依据。没有调用图像生成工具。

字体使用运行时 `SystemFont`，优先 Microsoft YaHei / Microsoft YaHei UI，缺失时尝试 Noto Sans CJK SC / Arial。本轮不把系统字体文件打进游戏；目标 Windows 设备的中文显示仍需导出包检查。源素材就是 `battle_board.gd` 的图形定义，无额外贴图、骨骼文件或授权素材。导出时随 Godot 项目编译该脚本；不生成或另存难维护的位图副本。

正式美术需要另行建立经过用户评审的配色、面部、装备层、锚点、朝向、动作时间与图标规范；程序占位可完整替换，保持规则接口不变。

## 验证证据与已知限制

初始视图通过 Godot 4.7.2 脚本解析检查。2026-09-18 已完成主界面集成，并从 Windows 导出包生成界面截图：中文字体、棋盘点击、可达格、粮仓目标、正常／加速／跳过不改规则及小窗口布局已有自动验证与截图复核。实际证据见 `docs/08-validation.md` 和 `docs/09-visual-review.md`。这些结果仍不构成真人逐帧动画观感或商业美术验收。

2026-09-18 对本文件负责范围的新增验证：以本机 Godot 4.7.2 headless editor 成功解析 `battle_board.gd`。行动环／标签与射程叠层现可由接口绘制；主流程接线、导出包截图和真人观察由主 AI 验证，尚未在此样板任务中伪称完成。跳过时会清除已有动画队列但不改规则快照；行动标识直接读当前快照，因而跳过后仍保留可读的当前行动者。加速只缩短现有移动、出手、命中和元素反馈的时间，标识持续跟随移动插值，直到规则快照更新。

主 AI 最终集成：导出包125/0，18张图；63格映射、范围与预览接线、合法目标、悬停清理、小窗口和速度只改表现已自动验证，重点截图已人工读取复核。待真人观察密集单位点击、移动/受击时序、元素连续反馈及最小窗口图例；正式方向与装备叠层仍未实现。

当前表现限制：尚无音频、完整骨骼、逐帧手绘、武器飞行物、逐个命中时刻的历史状态回放；展示使用结算后的规则快照，因此一次动作内多名死亡与多个串联移动主要用浮字、轨迹和日志解释。它是可玩机制的原创视觉占位，不是已经完成的商业美术样板。若批次演出难以理解，应由主 AI 扩展只读事件快照，不能让动画回调反向计算规则。
