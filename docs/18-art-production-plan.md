# 美术升级详细计划：人物、战场与佣兵团界面

更新：2026-09-20。设计基线：提交 `aeae553`，可玩版本0.1.5.1，Godot 4.7.2，现行战斗规则 `prototype-0.1.5`；美术候选评审基线见各批次记录。

**状态：第二轮方向已经锁定为H主导，E/G只少量补充写实结构与油画笔触，F不再使用。** 生产规范见[19 H主导人物美术标准](19-art-style-standard.md)，第二轮原始反馈见[反馈与修订](../art/validation/2026-09-20-refined-directions/FEEDBACK.md)。当前只推进一个角色的04武装、06倒地、07死亡修订样板；候选仍不是正式可组合库。下述数量、尺寸和验收阈值是用于组织生产的建议，样板测量后允许调整；不代表已实现内容、费用或发售承诺。

用户随后补充并确认：**倒下不一定死亡；战斗胜利后，倒地队员可能幸存并受重伤。** 本计划已将此纳入第四步。现行0.1.5.1仍是HP归零直接死亡，以下新流程尚未实现。

## 1. 要交付的体验与范围

目标是在当前旅行—事件—契约战斗—返营生活框架内，形成完整、统一且值得长时间观看的中世纪奇幻画面。玩家看得清不同人物的脸，能辨认穿戴、伤势与战场变化，常用操作通过图标找到；需要解释时，悬停或详细页能提供准确规则。

用户新增要求作为硬方向：伤痕、元素和尸体不能留下简陋程序占位痕迹；装备合身、层叠自然，无直接剪切边和块状阴影；UI边框大胆、有张力；技能、特质、性格和物品有专门生成的图标，默认尽量少文字。

覆盖当前9个主要页面、3类复用浮层、现有全部装备/技能/地点/物件，以及四步批次新增的招聘、契约、部署和人物后果界面。用一段完整游玩流程验收，不能只交几张宣传立绘或一屏好看的战斗截图。

当前仍是固定路线，不借美术升级加入自由探索、兽人/哥布林阵营、大量新武器规则、完整士气、繁衍或战斗中救起/复活。用户新确认的“倒地后战胜可能重伤幸存”进入本批第四步，和死亡美术一起设计。

## 2. 参考研究与原创视觉方向

研究记录见 [设定集分析](research/art-book-findings.md)。重点参考书中第6页分层与尸体、第7页护甲绘制、第9页世界层、第14页战场层、第48页旗帜和第51–60页装备，以及用户7张参考图。

推荐视觉语言为 **冷湿边境中的灰铁、旧布与余烬**，服务现有灰岸营地、雾林、雨夜粮仓与裂钟桥头：

- 人物：明显的骨相、鼻梁、眉弓和眼神，保留手绘笔触；脸与握持武器是第一视觉重点。普通人与高出身都有精心设计的脸，不把贵族画得更“主角化”。
- 以H的紧凑半身剪影、角色大小、大头比例和低矮铁皮椭圆底座为主标准：短腰自然贴进底座顶面，双手完整并高于腰线/底座上缘，不留下悬空、穿插或横向硬切。换甲和受伤不得改变整体标尺。
- 材质：保留H的清楚棕黑轮廓，少量吸收E/G的写实结构与轻度油画笔触。铁有冷硬反光和局部锤痕，皮革有弯折与磨边，衬甲有受力褶皱，链甲有随体积变化的密度，木头有断茬和纤维；细节不能密到破坏小尺寸轮廓。
- 色彩：环境以灰绿、土褐、冷石色为底，人物肤色、织物和徽记提供辨识；余烬橙、旧铜金与少量蓝绿色魔幻色作为焦点。不会把所有画面压成同一种脏棕。
- 光照：角色与装备采用固定左上主光、较冷的暗部和柔和接触阴影；火焰只作受控局部染光，不让装备本身的高光方向随场景随机改变。
- 阵营：自由团偏灰铁、深红封蜡与缝补旗布；雾林猎团偏苔绿、旧皮、结绳与牙饰；劫掠者用不对称旧甲、破布和劫掠痕迹。身份同时依靠轮廓、装饰和颜色，不只换红蓝。

“优于战场兄弟”落实为5项样板比较：更稳定自然的穿戴遮挡、更丰富但同一人的面部变化、更连续的装备/尸体身份、更细腻的元素及环境痕迹、更鲜明且少遮挡的原创UI。采用同屏实际尺寸对照，不以放大海报或素材数量宣布达标。

## 3. 制作流程与画质底线

采用已确认的方法：OpenAI生成/参考编辑 → 分层修整 → 定位与遮挡校准 → Godot组合 → 导出包验收。SpriteCook只作为可选的切图、动画或地块加工辅助，当前不采购、不建立依赖；选型理由见 [17](17-art-pipeline-selection.md)。

### 3.1 先固定母版，再扩充

先以一个H标准角色完成04武装、06倒地、07死亡，并做完一套攻击的预备、出手、命中、恢复、声音和特效。锁定光照、轮廓、比例、画布、锚点和接口，验证1×、加速与跳过后的可读性，再扩身体、脸部、轻/重甲、其他握持姿态、地表/元素和UI。每次派生变体都引用批准的母版，明确“允许变化”和“必须保持”的部位。

不能独立生成几十个全身人物后再强行拆层。先生成可审查的整体穿戴效果，确认结构；再按确定的层位制作独立部件，重组后与整体效果对照。只改衣服、伤势或表情时必须保留人物身份和未变装备。

### 3.2 建议的资源规格

| 类别 | 工作母版建议 | 实際游戏用途与检查 |
| --- | --- | --- |
| 人类棋子部件 | 统一768×704 RGBA工作画布，是当前96×88逻辑画布的8倍；模型原始输出先规整，保留有意留白 | 可派生384×352和192×176运行资源，按真实用途选择；在战场大小及近景分别验收，换装不能各自按可见边缘缩放 |
| 营地肖像 | 从同一身体/身份/装备母版合成较大预览 | 不另外生成一张对不上战场的脸；大图不能掩盖战场缩小时不可辨的问题 |
| 技能与状态图标 | 通常256×256母版，复杂主体可用512；保持统一有效占比 | 按现有小徽记约24–32和操作图标约40–56逻辑像素另做精简导出；不直接把大插画缩成糊点 |
| 地块与过渡 | 同一六边格投影、尺寸、边缘规则 | 按现有格心与命中逻辑放置，地表透明边必须在六方向和合法叠层下检查 |
| UI边框 | 角件、可延展边、低对比内底、独立徽章 | 九宫格拉伸或平铺，角饰不变形；文字与按钮不是图片内烘焙的内容 |
| 特效/局部动画 | 单一动作序列共用画布、尺度和锚点 | 首尾衔接、加速与跳过均可用；仅为确需变化的局部制作逐帧，不为所有换装组合重绘角色 |

这些是加工后的资产规格，不是假设生成工具能一次精确输出。纹理采用适合手绘图的平滑采样与缩小策略；禁止默认最近邻放大造成块状阴影。图集保留边缘扩展和足够间隔，实际间隔随缩放测试确定。

统一登记地面原点、头颈、左右肩、左右握点、盾点、武器转轴与受击点；地面原点从当前约(48,76)逻辑坐标校准。较长武器和轨迹使用明确的额外边界，不能为防裁切随机改变人物缩放。左右目标优先驱动手/武器局部方向，不能直接镜像整个人物而把伤疤、盾手和装备装饰换边。

每件正式资源保留可编辑母版、透明部件、遮挡/接触阴影、来源记录、稳定ID、对应规则ID、版本和游戏内截图。记录工具、日期、能取得的模型信息、提示词/参考关系与修整内容；模型信息不可得时如实标明。可编辑母版可为分层编辑文件或无损PNG部件加完整组合清单，不只留一张扁平合成图。源文件与发布文件分开管理，避免把中间试稿打进游戏。

### 3.3 直接退回的画面

- 黑底、白底或地面上出现白边、黑晕、矩形裁切边、锯齿孔洞、悬浮部件。
- 全身光照一致性错误，领口/头发/手部被硬切，武器穿脸或握点脱手，内衬穿出金属甲。
- 用同一条红线代表所有伤口，用均匀黑裂线代表所有甲损，用圆点/三角形代替正式火焰和血迹。
- 阴影呈方块、像素台阶、明显重复马赛克；链甲或头发在缩小时出现闪烁/摩尔纹。
- 人物每次表情或损伤变化都像换了另一张脸；破损甲改变了原物品扣具、纹样或基础材质。
- 持械手缺失或低于腰线/底座上缘，站立腰部悬空或穿入底座，武器倚胸/倚肩、朝向与出手通道冲突；倒地/死亡仍携带底座，倒地撑肘起身、像安睡，或腰以下缺失成为明显切口。静态姿态通过后仍须验证预备—出手—命中—恢复及声音/特效。
- 图标主体难认、技能仅靠换底色区分、框饰抢过角色、持续特效盖住目标和行动信息。

程序继续负责组合、插值、颜色映射、粒子运动与规则提示，但正式可见的伤痕、火焰、烟、血迹和物件残骸必须有经过美术验收的形体与纹理。精确的射程、路径、合法格和命中反馈保留清楚的战术标示。

## 4. 人物身份、表情与伤痕

### 4.1 人物不是职业皮肤

首批目标12套可辨的人类脸部身份，覆盖不同骨相、年龄感、肤色与生活痕迹；8套发型、6套胡须作为兼容部件。数字为生产目标，不把组合乘积宣传成几百名独立手绘人物。

保留统一的颈部/头部装配范围，在这个范围内允许脸宽、眉骨、鼻形、颌线和耳形差异。优先使用完整的脸部身份母版，五官变化在同一脸内部编辑；避免任意拼鼻子和嘴形成接缝。头发、胡须分前后或遮挡版本，肤色与脸部阴影配套校准。

为同一身份制作4类活体面部表现：平静/专注、发力、短暂受击、持续负伤。持续表情只反映真实伤势或已保存性格，未实现士气时不随机显示“恐惧/崩溃”等有规则含义的状态。死亡姿态另配闭合/松弛面部，不能由一张站立痛苦脸旋转替代。

外观在人物创建或旧档首次迁移时确定并保存。新增加脸、发型或排序不会改变旧人；在役名册检查可见组合重复，敌群避免相邻多张同脸。有限库允许跨远征复用，但不得以无限不重复作交付承诺。

### 4.2 伤势有位置、体积与期限

样板先做4类视觉语言：局部擦伤、肿胀/淤青、流血伤口、已愈合旧疤。伤口顺着面部转折，改变局部皮肤颜色和体积，有合理边缘和血液走向；不能把整张脸盖成红色贴纸。

伤痕依附脸/身体局部坐标，受头盔、头发和衣物遮挡；布面渗血与皮肤伤口分开。新伤恢复时去掉血与肿胀，只有有来源的永久疤痕才保留。初始装饰性旧疤单独标识，不自动给予永久伤残效果。

当前总HP只足以驱动一般负伤程度，不据此生成失明、断臂或指定部位残疾。四步第4步的腿伤/膝伤通过已保存的伤势ID映射到可见绷带、动作和徽记；半身看不到的位置用图标和人物详情解释，不在脸上伪造对应伤口。

## 5. 装备自由组合与真实破损

### 5.1 结构层与规则槽分开

建议装配顺序按部位处理：背部披挂/背负物 → 身体与内衣 → 衬甲 → 主护甲 → 外罩布与腰带 → 颈部/头部 → 前后发须及头部组件 → 手/武器 → 前景盾或护臂。颈甲、胡须、兜帽和手臂存在交叉遮挡，用局部蒙版与拆分部件解决，不仅靠一条全局层序。

当前只有武器和护甲两个规则槽。首批让4件护甲各自拥有真实可见的内衬、主体和扣带层；适合的兜帽/护颈可作为该装备的成套视觉组件。独立头盔、披风、副手只预留接口及小样，不假装已能独立购买、叠加属性或分别损坏。后续加槽位时拆出对应组件，已有主体素材继续复用。

首批使用一个共同肩颈/握点兼容模板，外部体积通过衣甲轮廓区分。宽肩、矮小等第二体型只有在适配表验证后扩展，不对任意身体随意非等比拉伸装备。脸型差异不要求重画所有甲。

### 5.3 同一件甲的四档状态

每甲目标为完好、受损、重损、耗尽4档；拟沿用现有约67%/30%分界并增加0耐久明确外观，属于表现映射，不改战斗减伤规则。分界最终以预览和实际读数核验。

- 衬甲：纤维磨毛、线缝松脱、撕口与局部填料外露。
- 皮甲：摩擦失色、裂口与扣带松脱，破损沿受力部位发生。
- 钉甲：外层撕裂、铆钉脱落、局部内片露出或变形。
- 链甲：链环断开、局部塌陷与内衬暴露，不能画成与板甲相同的长裂缝。

修理逆转装备损伤显示，人物血迹/永久疤痕不随修甲清除。0护甲仍保留该装备的破损身份，不自动裸体。武器及盾目前无独立消耗耐久：设计正常使用痕迹可以，战斗中逐步断裂或盾毁需先有真实规则，不能沿用总护甲值冒充独立盾损。

## 6. 倒地、重伤幸存、死亡与战后痕迹

### 6.1 最新规则方向与状态区分

现行版本 `hp <= 0` 直接死亡，这一事实不再作为新设计目标。按用户最新要求，第四步调整为：**在战斗中倒地失去战斗能力 → 胜利后清点伤亡 → 有机会重伤幸存，也可能确认死亡**。倒地不是同场复活，也不自动产生战中治疗救起动作。

| 状态 | 规则含义 | 画面与说明 |
| --- | --- | --- |
| 存活负伤 | 仍能行动，按已有伤势承担限制 | 活体、负伤表情/局部血迹，不能摆尸体姿态 |
| 倒地待清点 | 不能行动/被选作行动者，不计入有效战斗人数；生死尚未结算 | 身体保持完整的倒伏姿态、倒地标记；悬停说明“失去战斗能力，战后清点”，不使用骷髅/阵亡措辞或断头图 |
| 重伤幸存 | 战胜伤亡结算后存活，获得有来源的重伤 | 结算肖像有重伤/包扎图标；返营状态明确，原人、装备与履历延续 |
| 确认死亡 | 伤亡结算给出的终局结果 | 尸体/死亡图标、阵亡名单与纪念册；不可由菜单或读档重抽 |

待清点者不显示稳定呼吸、睁眼求救等确定存活信号，也不提前显示只可能致死的外观；靠姿态和明确标记表达不确定性。存活/死亡一经结算才切换相应结果。装甲、身份、已有伤痕始终保持一致。

### 6.2 伤亡结算建议（具体平衡待验证）

- 战斗创建时保存独立伤亡种子与算法版本，为固定队员ID派生专属抽样依据；首次倒地时把该值、来源行动、伤亡ID和待结算状态写入同一战斗快照并随动作保存。开关结果页、重播动画或载入同一战前存档都不会重新洗生死。伤亡随机流不干扰战斗命中序列，不依据出图/尸体姿态抽概率。
- 胜利后，对每名本场倒地者写入一次伤亡结果：重伤幸存或死亡。幸存者HP设置为规则规定的合法正值并保存重伤，不能留下0HP却已存活的矛盾快照。幸存必有真实重伤及恢复成本，不是回满血；具体幸存率、恢复天数和永久伤残关联需按玩法验证，不在本美术计划写死。
- 顺序为冻结战果 → 清点倒地者 → 确定并保存伤亡/重伤 → 处理装备保留或损失 → 奖励与经验 → 后续人物事件与返营。不能先写纪念册/删除装备，再根据幸存结果“复活”。所有效果使用同一结算实例防重复。
- 暂定仅胜利、控制战场时有这项战后找回机会。撤退/战败时未能撤出的倒地者按失败伤亡处理，存活撤退者按原规则保留；这是需要明确预告和试玩的本批提案，不是用户已确认的概率或失败规则。失踪、俘虏、救援合同另列候选，不自动扩展。
- 先覆盖持久名册中的人类与战犬；犬用适合动物的重伤状态，不套人类性格与膝伤文案。敌方首批只处理失能/退出本战与已有战果，不扩俘虏或招降；通用“倒地”也不宣称敌方必然死亡。
- 重伤幸存者建议先有短期休养禁战，再转为可恢复伤势，具体条件明示；有永久伤残时与暂时恢复分开。参加过有效战斗的幸存者按最终存活与原经验资格结算，不因倒地多领一份经验或免费得到性格/强力专长。
- 同一战斗进行中倒地者不重新上场；团灭判定统计仍有作战能力的单位，不因名单中的待清点者无限拖住战斗。双方同回合同时失能、战犬仍能行动等边界由统一胜负规则明确并测试。
- 旧档中已经确认死亡的角色不复活，旧进行中的战斗保持其规则版本；新规则从下一场新战斗启用。不能把旧版日志里“倒下”反解释成尚未死亡。

### 6.3 倒伏与尸体资产

人类目标为侧倒、俯伏2种倒伏构图，犬制作专用侧卧构图，再区分待清点与确认死亡。倒地和死亡都移除站立底座；服装与头部随姿态调整，有地面接触、压褶与重量，装备和头发保持身份。不把站立人物旋转90度，不用叉号或通用骨堆替代，也不把所有死者画成相同血团。

两个姿态先做可用于待清点者的完整身体母版，再派生确认死亡的脸部/血迹终态；护甲倒伏层可复用，不能因状态变化换成另一件甲。确认死亡延续用户认可的E07处理原则：身体、头部、双臂、衣甲、伤口和落地关系形成专用整体终态，不能把正常模块散放成零件堆。E07不代表所有死亡都必须斩首，终态仍读取规则或已保存的表现ID。4种甲均有倒伏适配件，脸/头发使用对应姿态或正确遮挡，武器仍能辨认。先保证一套侧倒可用，再完成第二姿态；首批不自行扩展新的断肢、斩首或尸体搜刮规则。

倒伏/尸体默认从战斗unit快照中的生命状态、身份、装备、耐久、位置确定性派生，不另建一份能决定生死或战利品的尸体实体。需要姿态选择时，将`fall_pose_id`等表现字段保存在同一unit表现快照；重复播放和读档不再生成一次。动态阴影/血迹也优先从既有事件和状态重建。

表现顺序为：规则确定本场失能 → 短暂失衡/落地 → 待清点倒伏 → 战果与伤亡结果 → 对应结果肖像/尸体。已确认死亡直接走死亡终态。倒伏对象留至本场结束，活人与战术提示有视觉/交互优先权；本批不因为换贴图新增格子阻挡、攻击倒地者或掉落物拾取。加速/跳过落到同一当前已知状态，不提前透露未结算结果。

尸体血迹及烧焦痕只在来源事件支持时出现。美术地面残留与仍有伤害的火区外观要分开：余烬/焦痕不能冒充有效危险格。

## 7. 战场、世界与元素表现

### 7.1 战场分层

基础土/草/碎石材质 → 六方向边缘过渡 → 低矮装饰/车辙 → 油水与旧痕 → 物件/尸体 → 活体人物 → 火焰与蒸汽等效果 → 必要战术提示。实际遮挡按角色脚点和效果高度细分，火焰可在人物前后有不同部分，不能用整屏覆盖层吞掉角色。

当前dry是规则上的普通地面；可在不改规则的前提下有草地、泥土、石路三种视觉材料。装饰性石头和树林边缘不暗示额外阻挡/减速；与可互动木障、油罐、水桶、粮袋在形体与提示上区分。

首批制作三种底材、各2–3种局部变化；常见接壤配对有六方向过渡。大面积用不规则草边、脚印、碎石、车辙打散重复，避免每格中心出现同一簇草。装饰布局使用独立固定视觉种子，不消耗战斗随机序列，读档不跳图案。

4类物件分别有完好、明显受损、摧毁残留：油罐为陶片与可读油渍，水桶为桶箍/湿木与水迹，木障为断木与支架，粮袋为破布与散粮。是否产生油水/火仍由现有规则决定；不能因画了液体而自行改变格子状态。

### 7.2 元素和打击反馈

| 表现 | 正式素材与动作 | 必须保持的辨识 |
| --- | --- | --- |
| 油 | 不规则薄膜、深色渗透与少量反光，边缘适配地面 | 与阴影及普通泥地可分，危险提示准确落格 |
| 水 | 浅水边缘、涟漪/溅水短序列与湿地反光 | 不画成油；没有水的格不出现持续水态 |
| 火 | 手绘焰舌序列、火星、热源核心、短烟与落地余烬 | 火格边界可读，人物脸和目标轮廓不长期消失 |
| 蒸汽 | 柔软、有方向和体积的云团，前后层交错 | 保留真实遮挡规则的提示；切换/消失无硬矩形边 |
| 武器接触 | 刃光短弧、木屑、金属碎屑/火星按命中材质选择 | 命中、格挡、破甲、落空不同；不每次都同一爆闪 |
| 肉体受击 | 局部形变/退让、短血滴和对应面部反应 | HP/伤势结果先由规则确定，动画不追加伤害 |
| 死亡/物件破坏 | 落地重量、专用碎片、尘土与残局 | 加速和跳过后终态一致，不残留输入锁 |

保留已有反馈的节奏和信息价值，把简陋形状升级为统一画风的精细素材。支持减少闪光/摇屏等表现强度，降低强度后关键信息依旧可读；不借此改变命中、范围或结算。

### 7.3 世界与营地

六处地标分别设计：灰岸营地的帐篷/火堆与军需架、泥岸渡口的栈桥/渡船、碎石山脊的岩脊与旧路、雾林边缘的树冠/猎径、雨夜粮仓的粮仓群与湿地、裂钟桥头的石桥/破钟标志。地点外轮廓和局部色块不同，即使不常显名称也能认出。

世界地图使用连续地貌、道路、河流和独立地标，不把当前路线画成几根浮在线上的按钮。地图美术层为未来自由移动保留连续空间，但当前只开放既有路线交互。

营地以可读的生活场景作为背景与入口锚点：人物/训练、军需、招聘、出征和休养分区；保持现有菜单可达性。事件和成长页用原创局部插图、人物肖像与徽记建立气氛，文字故事保留。至少现有6类事件均有对应视觉主题，可共享背景，不能每次换成无关的通用插图。

## 8. UI：强轮廓、少文字、按需解释

### 8.1 边框的张力来自结构

主视觉为锻铁骨架、磨亮的边缘、深色皮革内底、少量断旗布与封蜡。当前角色栏可采用不对称肩甲式角饰；技能槽像镶嵌的珐琅徽片；行动顺序用带团纹的窄带；重要确认页用封蜡/契约角饰。普通按钮保留安静的中心，华丽装饰集中在当前人物、主操作和标题节点。

角件、边条、底板和徽章独立制作。九宫格延展不能拉长铆钉或压扁纹章；边饰没有交互时不拦截鼠标。画面张力不能来自四周厚框、满屏高亮或永久动效。

战场保持左上可收展战报、底部人物/技能/物品、底部行动序列。上方只保留必要回合/目标与系统操作。拟以标准画面常驻HUD遮挡不超过约20%为样板检查目标，最终用现有1440×900和最低1180×740布局测量；不为凑比例缩小到无法点击。

### 8.2 图标语法

技能、专长/能力、性格、物品分别有独立主体图案；同类共享绘画、光照和边框语法。主动操作用清楚的方形槽，特质/性格用不同轮廓徽章，消耗品用实体器物剪影，暂时状态带期限标记，永久变化带固定角记。颜色与形状共同表达状态，不能全靠红绿。

`attack`虽是一个规则动作，显示图标应按已持武器风格选择挥刃、枪刺、弓射等主体；标题和详细伤害仍读取同一动作。防御与盾击、推开与移动、跟随与召回必须用不同构图。每张技能图标默认保留简短费用数字、可用数量/期限或快捷键所需标记，名称放在悬停说明。

图标的普通、悬停、按下、当前选中、不可用、冷却/次数不足状态由统一底框与轻量效果表达，不为每个状态重新画完整图标。持续选中有稳定轮廓，不仅一瞬间闪光；不可用原因能被键盘聚焦和悬停读取。

### 8.3 三层信息

| 层级 | 默认内容 | 操作 |
| --- | --- | --- |
| 即时识别 | 肖像、图标、HP/甲/AP色条及数字、目标/费用关键数字；技能不常驻长名称 | 看一眼定位人物、动作与资源 |
| 悬停说明 | 名称、作用、费用/射程、当前可用性和主要限制；目标卡仍保持紧凑 | 鼠标悬停或键盘聚焦，延迟建议约180–250ms并依据试玩调整 |
| 深入检查 | 完整规则、属性来源、状态期限、装备明细、履历 | 沿用Alt切换详情；超长正文在受限区域滚动 |

“少文字”不隐藏决定所需信息：招聘价与维护周期、路线天数/粮耗、契约危险/期限/失败后果、伤势恶化与永久死亡、解雇损失，在做决定的面板上仍有短语和数字。故事、人物履历、契约条款和教学可保留正文；战斗底栏不承载长解释。提供可选短标签辅助初识图标，默认关闭常驻技能名称。

悬浮卡避开目标脸、鼠标、底部操作和确认按钮；出屏时换侧，细节卡可锁定阅读；不造成点击穿透。被头盔遮住脸的人仍通过头像、武器、位置和当前行动标记可辨。

| 武器 | 10套设计，2套含盾；立姿与2倒伏摆放配置 | 至少30个姿态配置逐件检查；硬质武器可复用图层加摆放/阴影配置，确需透视变化时才新画适配件 |
| 身体与犬 | 1人类身体模板及2倒伏适配；1犬母版 | 身体3姿态与所有甲验证；犬健康/负伤/待清点/确认死亡4状态至少各1，动作序列另计 |
| 普通地面 | 草/土/碎石3材质，各3个底材变化为初始目标 | 9底材；草-土、土-石、草-石3对×6方向=18边缘件，再检查多边与三材质交点，必要角补件计入追加适配成本 |
| 物件 | 4母件，各完好/受损/毁坏3态 | 12状态，破坏序列与规则产生的液体另计；不把同一碎木图当4份完成 |
| UI | 14–18类组件母件/装饰，常用5种交互状态 | 状态优先共用底板与焦点/按下/禁用叠层；每类适用状态逐项验收，不能称18张图就做完全部UI |
| 动画/特效 | 10–14家族；常规短序列先按6–12关键帧/单元估算 | 仅逐帧家族按实际帧数计输出；部件插值不按全人物逐帧展开。样板测得通过率后锁帧数上限与总量，当前无总费用承诺 |

伤痕4类为设计母版数量，不等于只要4张通用贴纸；适配到12脸、不同身体/衣甲的数量在A阶段逐行登记。若预算不足，先减少第二姿态、额外发须或罕见变体的数量并明确阶段范围，不能以错位或低质通用件假装覆盖完成。

### 9.2 用可达清单判断完整度

A阶段建立版本化`visual_asset_manifest`，从数据定义、图标调用和实际页面分支共同收集需求，再由人工复核。字段至少包含稳定语义ID、规则/表现来源、页面/状态、负责人、正式资源ID与版本、可访问文本、允许回退范围、验收证据；图标别名也明确登记。

30个核心语义之外，清单还要覆盖角色/武器风格、火/蒸汽/破甲、物件、倒地/死亡、行动顺序、结束/等待/撤退、资源、导航、保存、错误与提示。开发运行时发现未知图标ID要报告，不能静默退成一把剑。正式发布要求所有可达语义零缺件，不能只拿本文手列数量作分母。

页面清单用独立状态键，以下是计划键，尚非现行节点名称：`title`、`company_setup`、`continue`、`camp`、`world`、`travel`、`returning`、`event`、`prebattle`、`battle`、`growth`、`character`、`equipment`，以及`dialog`、`log`、`inspect_compact`、`inspect_detail`。每页记录适用的normal/empty/disabled/error/long_content；特殊状态如零资源、缺席队员、缺犬主、已失能、伤亡结果另列，不能因共用背景而省验。

## 10. 工程接口与存档约束

| 接口 | 责任与约束 |
| --- | --- |
| 人物外观记录 | 保存外观模式版本、身体模板、脸/发/须/配色稳定ID和已有装饰疤痕；角色出身只影响合法候选，不决定唯一脸。敌方外观按战斗实例ID＋unit ID确定并保存在该战斗快照，不能仅用每战重复的enemy_0等ID取脸 |
| 装备表现清单 | 规则definition_id映射层、画布、锚点、遮挡、耐久档和姿态；武器实例/护甲实例继续是规则来源 |
| 状态外观解析 | 输入HP、耐久、已发生伤势/性格、死亡和当前动作；只返回表现数据，不写伤害、费用、经验或随机状态 |
| 倒地与伤亡记录 | unit快照区分active/incapacitated/dead等明确语义；战后伤亡结果与重伤按稳定结算ID保存。尸体从同一快照派生，只按需保存倒伏姿态等表现字段，不创建第二个生死/装备状态来源 |
| 图标映射 | 以visual_asset_manifest覆盖所有可达规则/表现ID及页面状态，提供正式图标与可访问名称/说明；开发时报告缺件，正式覆盖版不能静默使用未知菱形、通用剑或文字占位 |
| 视觉版本与迁移 | 新旧资源ID保留别名或明确保底；旧角色首次确定外观后保存，未来扩库不重抽。旧战斗敌人也按锁定目录版本、战斗实例与unit ID一次映射并保存；旧进行中战斗规则/RNG不变，外观迁移不重生成战斗 |
| 诊断与回退 | 开发阶段保留清楚标记的程序回退以定位缺件；正式交付路径出现回退判为覆盖失败，不把它算正式美术 |

优先继续使用当前共享人物入口、场景坐标和规则/表现分离架构。营地、军需、招聘、战场、行动条与纪念册使用同一外观来源。美术清单独立于背包规则，避免每新增图标都改战斗代码。

代码后续预计修改范围：人物合成器与资源解析、战场人物/尸体/地块/特效、世界地图和各页面主题、图标与悬浮组件、必要的外观保存迁移。每个文件在一个阶段只指定一名写入负责人，接口冻结后才能平行填充资源。

## 11. 与四步功能合并的实施顺序

总体顺序保留 [16四步批次](16-next-four-steps.md)，先加入共享美术基础和代表切片，再按功能依赖连续开发，最终一起导出。阶段推进依据验收，不以生成数量替代完成度。

| 阶段 | 玩家能看到的结果 | 工作与完成门 |
| --- | --- | --- |
| A：风格与接口样板 | 一个H标准角色有清楚的穿戴、伤损、倒地/死亡及完整攻击反馈；一套强轮廓底栏 | 先用1固定人物完成04/06/07与一套预备—出手—命中—恢复、声音、特效，验证组合、透明边、锚点、正常缩放、1×/加速/跳过和资源成本；通过后再补剑盾/长枪/弓、轻/重2甲及损伤、犬、3×3地表与物件、火/蒸汽、核心图标和边框 |
| B：现有框架全面换装 | 当前旅行—事件—粮仓战斗—营地流程中全部主要对象和页面有统一正式美术 | 按版本化清单覆盖全部可达ID；补齐面容、10武器、4甲、地点、事件、UI与特效。导出证据覆盖两团、两路线、6事件、胜败撤退、换装/修理和旧档各阶段；未实现的倒地幸存样板此时仍不混入旧规则 |
| C：招聘与后勤 | 候选肖像、可辨出身、本领徽记、费用和维护预告 | 四步第1步；候选生成即固化身份，招募后同脸同装备，刷新与扣费不因页面重开变化；零钱粮恢复路线仍清楚 |
| D：差异契约 | 三类契约有各自目标图标、场景标志和结果呈现 | 四步第2步；复用环境组件，通过目标布局和物件建立差别，新增两个样板；失败/撤退与一次结算均验证 |
| E：出战替补部署 | 名册、替补和阵型使用一致人物外观，伤员与犬主关系易读 | 四步第3步；锁定出征名单，合法格和风险显示，旧战斗不重排，候补不多领经验 |
| F：倒地伤亡与人物后果 | 倒地待清点、重伤幸存、确认死亡可分；临时伤势、永久伤残和性格有图标与履历 | 四步第4步；先完成用户新要求的战后伤亡事务，再接伤势/性格。锁定ID/来源/期限；事件基于真实幸存、带伤撤出或保护经历，不增加战斗中复活 |
| G：整批发布检查 | 可连续游玩的正式美术验证版 | 覆盖正常与失败流程、各种画幅、动画速度、旧档、三次败退恢复、性能与全部资产映射；用实际Windows导出验收并更新三机交接 |

A的样板在真实游戏尺寸下供用户评审，属于外观方向与批量成本检查，不再重复询问是否采用已经批准的方法。批量返工风险较大时先修样板；规则小修、资产校准和明确范围内的测试正常推进。

A放行时还须提供可计算的产能表：每家族平均尝试数、通过率、修整时间、实际状态/帧输出数、文件/纹理占用，以及整批低/中/高工作量估算。若同一母版连续两轮关键穿戴错误未收敛，或单位验收成本超过样板估算两倍，暂停该家族扩量、修母版/缩减额外变体，并向用户说明具体影响；这些是生产检查线，不是已批准现金预算。

最多同时3名子代理。接口和共享文件串行，资源家族可独立分工；不能让多个代理各自生成一套画风再合并。本轮已用Sol分别做覆盖盘点、视觉规范和独立验收建议，没有运行图像生成。

成本记录按家族记：尝试数、通过数、修整时间、生成/工具用量、返工原因和已用费用（能取得账单时）。样板后再给出整批估算；未测通过率前不报价承诺。不采购SpriteCook订阅，除非对照样板证明它节省总工作量且用户授权对应支出。

优先资源给脸、装备适配、常用图标、战场和UI边框；远景小装饰复用材质，先覆盖当前内容，延后额外敌族、第二体型、多方向和大量罕见动画。减少重复生成与无意义放大，不能靠把关键脸/甲/伤痕降成程序线条来省成本。

### 12.1 三台电脑的资产交接

当前仓库公开，源码与文档已有Git同步。正式资产的最低可重建来源采用“无损部件PNG＋组合/定位/来源清单”，连同运行时资源与导入设置进入同一版本；不能只在第三台电脑保留唯一母版。可选分层编辑文件保留为补充，不成为其他机器无法取得的隐藏依赖。

| 内容 | 计划存放与交接方式 |
| --- | --- |
| 清单、定位、遮挡定义、提示词/来源说明、规则映射、许可说明 | 文本入Git，素材版本与代码版本配套 |
| 本项目正式部件PNG/图集与必要可编辑源 | 小批直接入库并记录hash；A阶段测体积与三机拉取后再定大二进制策略。预计超出普通Git合理体积或托管限制前评估LFS，不先自动采购存储/创建外部服务 |
| 可重建预览、导出包、运行截图、废弃试稿 | 留`builds/`等忽略目录；试玩包可按现有方式在三机复制，不能代替正式源的版本管理 |
| 用户设定集与参考图 | 最新U33明确要求PDF原件同步GitHub，保存于references/battle-brothers并记来源/哈希；截图和渲染预览继续本地参考。第三方参考不进入游戏导出 |

每件正式资产记录内容hash、母版/输出版本、参考来源、生成工具/日期、可得的模型信息、修整和来源/授权状态。其他机器拉取后运行清单校验、导入并构建；源或hash缺失应报告，不能现场临时再生成一张“差不多”的图替换。若最终选LFS，需一并验证三机拉取与不含本机缓存的干净重建，相关工具与额度另核对。

### 13.2 实际尺寸与导出

至少检查1440×900逻辑基准、1180×740最低窗口、1920×1080和2560×1440输出；Windows 100%/125%/150%缩放。装备在黑/白/地表三底上看边缘，在实际战场大小看可读性，在近景看材质，不只查原图。UI目标是无截断、重叠与模糊，不强行缩字保住装饰。

图标理解用实际可执行动作做快速辨识，特别检查防御/盾击、移动/推开、跟随/召回、临时/永久伤势及倒地/死亡。费用、期限和风险数字由真人快速找出；误认付费、误认确认死亡者仍可救、把待清点者当必死或误把火区当焦痕均直接退回。审美方向和情绪冲击力需要用户试玩判断，自动测试不能代替。

每条截图/录像证据记录提交、构建、状态夹具、分辨率、缩放和素材版本。源码预检通过后必须从真实Windows导出包跑完整流程，不能只验编辑器样板。

### 13.3 规则、存档与性能

- 同一个存档/种子，切换画质、动画速度、跳过与重复打开菜单，伤害、行动、经济、奖励和RNG不变。
- 招聘预览到入团、军需换装到战场、死亡到纪念册，身份和装备来源一致；旧档`camp/event/travel/battle/growth/returning`均保持合法，未知版本保留原档并明确报错。
- 外观升级不重抽人物、事件或契约；尸体和场景残留保存后不复制或漏掉，不改变碰撞和战利品。
- 新伤亡结算覆盖战胜幸存、战胜死亡、多名倒地者、战败/撤退、全员失能、人犬混合；检查同战不复起、幸存重伤与装备保留、死亡损失、经验只发一次、事件只读最终结果。结算中断重载不重抽、不先删人再复活，旧已死者永久保持原结果。
- 在本机锁定分辨率记录美术升级前后帧时间、内存、加载和换装首次卡顿。目标为普通战场流畅60fps、换装/技能点击无可感持续卡顿；若未测硬件和资源预算，不先承诺跨三台机相同表现。伤亡机制提升战斗规则版本，不能以纯美术补丁名义改变旧进行中战斗的生死结果。
- 大图不逐帧重建/重新读取，常用部件预加载并缓存合成；特效分层与数量有上限，优先保证角色和规则提示。其他两台电脑单独记实测结果。
