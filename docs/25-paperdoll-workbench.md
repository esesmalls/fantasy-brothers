## 为什么做在 Godot 里

现阶段需要同一底座、共同坐标下的穿戴校准。工作台直接调用静态样板的渲染、裁取和武器动作代码，避免浏览器里看着合身、进游戏却发生偏移。复用现有引擎，无新增付费编辑器依赖；U50／U51新试样的图像生成另记在各批次来源记录中。

保持 H、无手半身、固定身体与独立武器动作。底座宽64与现行盘面仍是默认；现可在工具内改锚点和裁取范围，不改则已有资产不变。人物和衣物可以在共同窗口里调整，完整原画不修改。Spine／三维降二维仍为未来方案。

## 使用

双击根目录 `Paperdoll.cmd`。启动器会检查本地源码时间，有更新或缺少导出包时自动重建。首次准备引擎仍按 README 的 `tools/setup.ps1` 执行。导出程序位于 `builds/paperdoll/windows/FantasyBrothers-Paperdoll.exe`。

1. 在左侧按组件类型、层位置或名称查看部件。不同分类里的部件可以一起勾选，再点一次取消；点分类名称会选中或取消整组，其他分类的勾选会保留。选择衣甲／武器会同步预览装备。人物整体用于一起平移头身衣甲。多选时数值在各自原值上增减，需要对齐时用右侧「对齐参数」。子部件和父组件或人物整体一起选中时，平移只记在上层，画面上只走一次。
2. 在中央从已选部件上拖动，或在右侧输入左右、上下、等比大小和旋转。空白处拖动可框选看得见的部件，Shift 框选为追加。选盘面时改裁取中心／半径／顶边。Alt＋拖动旋转，中键平移视图，“定位选中部件”找回移远的部件。方向键每次0.25逻辑像素，Shift＋方向键每次1像素。正X向右、正Y向下。
3. 用“叠加 v3 基准”、图层开关与浅／深背景检查领口和遮挡；下方始终保留当前及基准的待机小图。放大倍率会随可用画布收敛，弓保留额外飞行空间。
4. 切换“穿戴组合检查”查看亚麻、绗缝、链甲与伤损；“战场尺寸检查”看1×／2×相邻棋子的阅读效果。“内外层检查”移除头、武器和底座，查看同一外衣下不同真实内层；诊断视图不是新增战场美术。
5. 在“装配与对照”里播放剑／矛／弓，拖动进度条暂停检查；小窗口右侧可以滚动。
6. “保存调整”存一份 JSON 草案，“导出候选”另存完整候选目录。“截图”保存当前实际画面。候选不会自动替换正式资源。

Ctrl＋S保存，Ctrl＋Z撤销，Ctrl＋Y或Ctrl＋Shift＋Z重做；每次拖动／旋转算一步，部件启用也可撤销，最多100步。关闭未保存草案会提示；打开另一草案前有提醒，载入前状态也可撤销恢复。

## 本轮范围与边界

| 能调整／检查 | 约束 |
| --- | --- |
| 人物整体 | 仅平移 |
| 底座锚点、盘面裁取 | 可调；默认等于现行硬编码范围，见[28](28-paperdoll-authoring.md) |
| 头部 | 正常／受伤同步；本批只有一个身份 |
| 身体、内衣、亚麻、绗缝、链甲 | 独立位移、等比大小及旋转；甲损与完好同步 |
| 剑、矛、弓、盾 | 独立位移、等比大小及旋转；弓上箭跟随；武器路径可编写 |
| 发型、胡须、伤痕、绷带、血迹 | 附着头部／身体；局部调整；启用随草案保存 |
| 多选部件 | 勾选后按各自原值增减；和父组件或人物整体一起平移时只走一次；「对齐参数」才写成相同值 |
| 框选 | 空白处拖动选中可见部件；Shift 追加 |
| 图层开关、背景、基准叠图 | 临时检查视图，不保存为装备状态 |

位移±128逻辑像素，等比大小25%–300%，部件旋转±180°；大幅调整会提示复看。自动检查不能判断领口是否好看，不要用缩放弥补原画朝向或结构错误。

本批亚麻没有破损变体，组合表明确标示。U51将裸身与基础内衣分开，新增一套头面附着试样；身体已按追加反馈缩小、侧向重绘，待目视复评，详见27。盘面、底座锚点与武器关键帧现可在工具内调整，默认仍是现行范围。没有任意PNG导入或全身动画套件。层高可在工具里调整绘制先后，默认仍是现行顺序，只有改过才保存。没有新增头盔、动物、倒伏或死亡模块。工具没有战役存档入口，游戏版本仍0.1.5.1。

## 草案与候选

- 草案：未改盘面／动作／层高时仍为 schema2（`schema / kind / baseline_sha256 / modules_sha256 / edits / appearance`）；写入裁取或武器动作后为 schema3，另含 `crop` / `actions`；改过层高后为 schema4，另含 `layers`。当前示例在 `art/workbench/projects/h-user-calibrated-v2.json` 与 `h-modular-sample.json`。schema1／2旧草案继续可读，schema1保存自动指向新副本。
- 候选：套用草案后的完整 `catalog.json` 数据，可交工程接入复核；它不是可再次“打开配置”的草案。
- 基准摘要针对目录文件的字节。除明确验证过全部几何不变的v3白名单外，目录改变会拒绝旧草案；v3位移可保留，载入后标记待复看／重新保存。它不单独追踪PNG内容；原画更新仍须单独复看来源／版本记录。
- 文件必须使用完整路径。保存不允许写入当前程序资源、可执行文件目录或所在仓库的 `game` 源码目录。保存JSON先写临时文件并备份旧文件为 `.bak`，失败时给出错误；截图同样禁止覆盖这些目录的原画。
- 需要正式采用候选时，由agent在版本控制中核对改动、复跑装配检查并提交；工作台本身不“热替换”已认可基准。

旧schema1迁移示意（当前schema2示意见27；摘要从同版示例复制）：

```json
{
  "schema": 1,
  "kind": "fantasy-brothers-paperdoll",
  "baseline_sha256": "从同版基准示例复制",
  "edits": {
    "head": {"offset": [0.5, -0.25], "scale": 0.98},
    "spear": {"offset": [1, 0], "scale": 1.02}
  }
}
```

`edits` 旧组继续有效，新增 `skin / hair / beard / scar / bandage / blood`。`body` 保持指基础内衣，`skin` 才是裸身。局部变换→父部件变换→整体平移；不接受移动底座、任意路径或未知字段。当前源图比例、锚点、伤损配对与盘面沿用基准。

## Agent 使用同一入口

以下为项目根目录PowerShell；更换盘符时用当前仓库绝对路径。先复制基准示例为独立候选草案，再编辑 `edits`。

```powershell
$engine = '.\tools\godot\Godot_v4.7.2-stable_win64_console.exe'
# 建立新草案
& $engine --headless --path game --script res://tools/paperdoll_cli.gd -- '--new=S:/fantasy brothers/art/workbench/projects/my-fit.json'
# 校验；可选导出完整候选目录
& $engine --headless --path game --script res://tools/paperdoll_cli.gd -- '--input=S:/fantasy brothers/art/workbench/projects/my-fit.json' '--output=S:/fantasy brothers/builds/paperdoll/my-candidate.json'
# 在实际工作台中载入这份草案
& '.\builds\paperdoll\windows\FantasyBrothers-Paperdoll.exe' -- --paperdoll '--paperdoll-project=S:/fantasy brothers/art/workbench/projects/my-fit.json'
```

输出含 `ok / error / warnings / changed_groups`，无效配置退出码1且不套用；有效退出码0不代表通过美术评审。GUI与CLI共用校验、配对、变换与导出代码。
