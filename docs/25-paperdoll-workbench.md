# H 人物装配工作台

2026-09-20 · U49 · v3 已获用户基本认可，作为本轮固定装配基准。

2026-09-21 · U50增量：衣甲更换为真实透明开口的新原画，v3原图留作对照；固定几何不变。新增“内外层检查”和“损外层／损衬甲／全损”。详见[穿戴规范](26-nested-wear-standard.md)与[直接切换内层](../art/validation/2026-09-21-nested-wear/index.html)。以下U49基础功能继续有效；“本轮无图像生成”指U49历史，U50实际编辑了两张图集。

## 为什么做在 Godot 里

现阶段真正需要的是同一底座、共同坐标下的穿戴校准，而非另建骨骼动画编辑器。工作台直接调用静态样板的渲染、裁取和武器动作代码，避免浏览器里看着合身、进游戏却发生偏移。复用现有引擎，无新增付费依赖、图片生成或资产加工费用。

保持 H、无手半身、固定身体与独立武器动作。底座宽64、盘面前半圆及层序固定；人物和衣物可以在共同窗口里调整，完整原画不修改。Spine／三维降二维仍为未来方案。

## 使用

双击根目录 `Paperdoll.cmd`。启动器会检查本地源码时间，有更新或缺少导出包时自动重建。首次准备引擎仍按 README 的 `tools/setup.ps1` 执行。导出程序位于 `builds/paperdoll/windows/FantasyBrothers-Paperdoll.exe`。

1. 在左侧选择头、衣甲或武器；选择衣甲／武器会同步预览装备。人物整体用于一起平移头身衣甲。
2. 在中央拖动，或在右侧输入左右、上下和等比大小。方向键每次0.25逻辑像素，Shift＋方向键每次1像素。正X向右、正Y向下。
3. 用“叠加 v3 基准”、图层开关与浅／深背景检查领口和遮挡；下方始终保留当前及基准的待机小图。放大倍率会随可用画布收敛，弓保留额外飞行空间。
4. 切换“穿戴组合检查”查看亚麻、绗缝、链甲与伤损；“战场尺寸检查”看1×／2×相邻棋子的阅读效果。“内外层检查”移除头、武器和底座，查看同一外衣下不同真实内层；诊断视图不是新增战场美术。
5. 在“装配与对照”里播放剑／矛／弓，拖动进度条暂停检查；小窗口右侧可以滚动。
6. “保存调整”存一份 JSON 草案，“导出候选”另存完整候选目录。“截图”保存当前实际画面。候选不会自动替换正式资源。

Ctrl＋S保存，Ctrl＋Z撤销，Ctrl＋Y重做；每次拖动算一步，最多保留100步。关闭未保存草案会提示；打开另一草案前有提醒，载入前状态也可撤销恢复。

## 本轮范围与边界

| 能调整／检查 | 约束 |
| --- | --- |
| 人物整体 | 仅平移，保持固定底座规格 |
| 头部 | 正常／受伤同步；本批只有一个身份 |
| 内衣、亚麻、绗缝、链甲 | 独立位移及等比大小；甲损与完好同步 |
| 剑、矛、弓、盾 | 独立位移及等比大小；弓上箭跟随，沿用现有动作 |
| 图层开关、背景、基准叠图 | 临时检查视图，不保存为装备状态 |

位移限于±20逻辑像素，等比大小70%–130%；大幅调整会提示复看。自动检查只能发现格式、配套状态和部分动作越界问题，不能判断领口是否好看。不要用缩放弥补原画朝向或结构错误。

本批亚麻没有破损变体，组合表明确标示；基础身体是素色内衣。没有引入旧A批次面容、头盔、发须、动物、倒伏或死亡的新模块。没有任意PNG导入、自由改层序、重新定底座或动画关键帧编辑。当前先满足这一套已认可小样的校准，再随通过评审的新增资产扩展部件注册表。工具没有战役存档入口，游戏版本仍0.1.5.1。

## 草案与候选

- 草案：`schema / kind / baseline_sha256 / edits` 四字段，适合人和agent交换、Git比较；当前示例在 `art/workbench/projects/h-nested-baseline.json`，旧 `h-v3-baseline.json` 保留为迁移样例。
- 候选：套用草案后的完整 `catalog.json` 数据，可交工程接入复核；它不是可再次“打开配置”的草案。
- 基准摘要针对目录文件的字节。除明确验证过全部几何不变的v3白名单外，目录改变会拒绝旧草案；v3位移可保留，载入后标记待复看／重新保存。它不单独追踪PNG内容；原画更新仍须单独复看来源／版本记录。
- 文件必须使用完整路径。保存不允许写入当前程序资源、可执行文件目录或所在仓库的 `game` 源码目录。保存JSON先写临时文件并备份旧文件为 `.bak`，失败时给出错误；截图同样禁止覆盖这些目录的原画。
- 需要正式采用候选时，由agent在版本控制中核对改动、复跑装配检查并提交；工作台本身不“热替换”已认可基准。

草案示意（摘要应从基准示例原样复制，不自行编造）：

```json
{
  "schema": 1,
  "kind": "fantasy-brothers-paperdoll",
  "baseline_sha256": "从同版基准示例复制",
  "edits": {
    "head": {"offset": [0.5, -0.25], "scale": 0.98},
    "spear": {"offset": [1, 0], "scale": 1.02}
  }
}
```

`edits` 可用组：`bust / head / body / linen / padded / mail / sword / spear / bow / shield`。不接受 `base`、任意文件路径或其他字段。`bust` 先平移头身衣甲，其他组再应用各自调整；原画比例、锚点、伤损配对、盘面窗口始终沿用基准。

## Agent 使用同一入口

以下为项目根目录PowerShell；更换盘符时用当前仓库绝对路径。先复制基准示例为独立候选草案，再编辑 `edits`。

```powershell
$engine = '.\tools\godot\Godot_v4.7.2-stable_win64_console.exe'
# 建立新草案
& $engine --headless --path game --script res://tools/paperdoll_cli.gd -- '--new=S:/fantasy brothers/art/workbench/projects/my-fit.json'
# 校验；可选导出完整候选目录
& $engine --headless --path game --script res://tools/paperdoll_cli.gd -- '--input=S:/fantasy brothers/art/workbench/projects/my-fit.json' '--output=S:/fantasy brothers/builds/paperdoll/my-candidate.json'
# 在实际工作台中载入这份草案
& '.\builds\paperdoll\windows\FantasyBrothers-Paperdoll.exe' -- --paperdoll '--paperdoll-project=S:/fantasy brothers/art/workbench/projects/my-fit.json'
```

输出含 `ok / error / warnings / changed_groups`，无效配置退出码1且不套用；有效退出码0不代表通过美术评审。GUI与CLI共用校验、配对、变换与导出代码。

## 验收

实际Windows包在1440×960与1180×740进行鼠标选择、拖动、数值输入、撤销重做、滚动、播放／逐帧、快捷键保存及重载测试。U49截图与[QA](../art/workbench/2026-09-20/QA.md)保留历史，当前见[U50嵌套验证](../art/validation/2026-09-21-nested-wear/QA.md)。旧v3目录／PNG归档保持原样，当前目录升级到新衣甲原画，没有扩全人物库。

后续以此工作台先验证第二个面容与现有衣甲的兼容，再补头盔／发须遮挡注册、更多护甲及不同状态；这些仍须小样验证，不因工具落地而自动批准全库量产。
