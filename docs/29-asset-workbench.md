# Paperdoll 资产表现编辑器

2026-09-23。当前入口为根目录 `Paperdoll.cmd`；旧 25／27／28 文档保留历史兼容说明。本工具调整资产的游戏表现，不决定角色装备、战斗数值或伤亡。

## 开始使用

启动器优先打开 `art/workbench/projects/current.asset.json`，这是从用户 `my_test-v2.json` 迁移的新副本。原草案和原 PNG 保留。也可以将工程 JSON 拖到启动器，或在文件菜单中打开。

左上是资产库：搜索名称／ID、分类下拉、标签筛选，双击加入参考组合。左下是场景层：点击名称选择，显列控制编辑可见性，锁列防止误改。独显、参考透明度、组合切换不改变游戏配置。右侧只显示当前对象属性；底部动作模式开关展开时间轴。两侧面板可拖分隔线调整宽度，也能从视图菜单隐藏。

常见操作：

- 单击单选，Ctrl 单击增减，Shift 在场景列表连续选择；空白拖动框选，Shift 框选追加。右键画布查看重叠候选，隐藏和完全遮挡对象可在列表中选中。
- V 选择、G 移动、R 旋转、S 缩放。滚轮缩放，空格／中键平移，F 定位，方向键微移，Shift 加速。多选默认共用中心，也可使用各自枢轴。
- 多选数值默认增量修改；勾选“设为统一值”才覆盖为相同值。父子同时移动只处理上层一次。编辑分组只组织选择，不建立游戏附着。
- Ctrl+Z 撤销、Ctrl+Shift+Z／Ctrl+Y 重做；Esc 取消进行中的画布或时间轴拖动。文字输入焦点不触发这些全局工具快捷键。
- 源图区域使用图片像素；位置／显示尺寸使用游戏逻辑像素；旋转使用度；枢轴使用图片显示区域的比例坐标。源图区域不破坏 PNG。
- “显示遮罩”控制游戏中的可见范围，支持矩形、盘面与另一资产轮廓。它与源图裁切不同。更改已有遮罩会影响引用该遮罩的全部资产。
- “恢复默认参数”恢复本工程迁移／导入时的基准；在适配配置中执行则移除该资产的覆盖。此操作可撤销。

## 导入、适配和动作

拖入 PNG 或点击导入，可以框选图集中的多个区域。多区域按输入 ID 加编号登记；不框选使用整张图片。复制到工程管理的 `images/` 后以内容哈希命名，保存来源文件名、哈希、导入工具和来源标记。导入仅增加资源，不会自动让游戏装备它。

当前编辑范围显示在画布上方：资产默认值或具名适配配置。“+ 适配”建立覆盖配置，未覆盖的参数继承默认值。新种类由资产的分类字段直接出现在库里，无需修改按钮枚举。agent 修改已保存工程后，点击刷新：无本地修改时重新读取，有未保存修改时提示先另存，避免覆盖。

资产可选填父资产 ID 与具名锚点。锚点面板用名称和 X/Y 数值编辑；更改父资产时保持当前世界位置。附着循环、失效锚点、无效遮罩会被校验拒绝。游戏可提供锚点上下文，或选择独立根坐标调用。

动作模式使用独立偏移轨道，不修改基础姿态。任意部件支持 X/Y 位移、旋转、X/Y 缩放和显隐。手动落帧，或打开默认关闭的自动关键帧后拖动。播放头支持拖动、逐帧、循环和速度控制；关键帧可多选、框选、拖动、复制到播放头及删除。轨道过多时滚轮滚动。插值支持 linear（线性）、smooth（平滑）、hold（保持），显隐始终阶跃。

时间轴事件面板编辑出手、接触等事件的 ID 和秒数。现有剑／矛／弓动作已经迁移，弓箭保持独立的表现轨迹。事件只调度画面反馈，不能扣血、消耗资源或改变命中。

## 保存、应用与恢复

“保存”写编辑工程；“应用”先展示变化，再校验并发布完整资源版本。发布目录是 `game/assets/art/paperdoll/`，`current.json` 指向不可变版本 JSON；导入图片也复制到发布资源目录。发布不带编辑场景、眼睛、锁、选择或基准。

每次写工程检查载入时的文件哈希；发布检查当前版本并持有目录锁，防止人和 agent 互相覆盖。失败不切换当前版本。“恢复上次应用”切回前一版本。异常退出留下 `.publish-lock` 时先确认无正在发布进程，再移除空锁目录重试。

开发运行时按版本指针重载数据；正式打包包含当前发布资源。推荐在重新进入场景或重启游戏后复看。已经发行到其他目录的旧 EXE 不会自动获得工程的新数据，需要重建或分发新资源。

首个发布版本来自用户已有校准，不包含验收用的测试图片。当前真实战场仍由原有样板入口和显式资产请求使用新版；没有给全角色库自动替换装备或扩展六向美术。

## agent 与运行时接口

工程格式 schema 5：`assets`、`adaptations`、`masks`、`actions`、`editor`、`game`，另有恢复用 `baseline`。资产 ID 与显示名称分开。旧 schema 1–4 在读取时迁移成新工程；关键帧排序并补齐稳定 ID 后再使用，原文件不覆盖。

GUI 和 CLI 共用 `asset_document.gd` 的校验、事务、导入和发布；`asset_visuals.gd` 共用绘制、变换、裁切、排序、命中与取样。`asset_runtime.gd` 是游戏调用入口。

PowerShell 示例（在仓库根目录）：

```powershell
$engine = '.\tools\godot\Godot_v4.7.2-stable_win64_console.exe'
$draft = (Resolve-Path '.\art\workbench\projects\current.asset.json').Path
& $engine --headless --path game --script res://tools/asset_cli.gd -- --command=list "--input=$draft"
& $engine --headless --path game --script res://tools/asset_cli.gd -- --command=validate "--input=$draft"
& $engine --headless --path game --script res://tools/asset_cli.gd -- --command=diff "--input=$draft"
```

命令还包括 `new`、`read --id=... --adaptation=...`、`import --image=绝对PNG路径 --id=... --name=... --category=... --rect=[x,y,w,h]`、`update --operations=绝对JSON路径`、`apply`、`rollback` 和 `preview`。修改命令必须指定 `--output=绝对工程路径`，允许写回已载入且未被外部修改的同一文件。apply/rollback 可传 `--expected-revision=版本`。结果输出 JSON，并通过进程退出码表示成功／失败。

事务示例：

```json
[
  {"id":"sword","field":"position","value":[2,-14.5]},
  {"id":"sword","field":"rotation","value":30,"adaptation":"small"}
]
```

动作、适配、遮罩和游戏外观对象可使用 `{"section":"actions","id":"wave","value":{...}}` 形式作为同一事务操作；全批校验失败则全部回滚。

`preview` 需有显示的 Godot 进程，不加 `--headless`；指定 `--output=PNG路径`，可用 `--id=资产1,资产2 --adaptation=... --action=... --time=秒 --zoom=4`。单件独立预览加 `--root=true`。输出为 640×640，调用同一表现层。

游戏单件调用 `AssetRuntime.draw_asset(canvas, asset_id, origin, zoom, adaptation, action_id, time, anchors, root_mode)`；返回诊断数组。默认独立根坐标模式。组合渲染使用游戏明确给出的资产 ID 列表；样板单位以精确装备 ID 表映射现有装备，未知 ID 不根据名称猜测。

## 验收与边界

自动验证入口：`tools/build_paperdoll.ps1`。先执行资产基础测试和旧兼容测试，再导出 Windows 包，并等待新包的 `--asset-smoke` 完成。证据保存在 `builds/asset-workbench/qa/`，包括小／大窗口、时间轴、图集导入、迁移前后比较与 JSON 报告。窗口输入由 Godot 输入事件和文件拖入处理路径驱动，不声称是人工鼠标试玩。

本次结果：资产基础 40、旧兼容 560、动作事件 39、战斗规则 129 项通过；Windows 导出窗口 37 项通过。迁移前后画面中色差超过 RGB 累计 0.3 的占用像素变化比例为 0（验收上限 3%）。真实战场移动／攻击／盾击／防御、倍速和跳过使用导出包执行成功，截图在 `builds/asset-workbench/battle/`。CLI 事务修改、适配读取及单件预览成功。

第一版为图片／图集资产和部件时间轴，不包含骨骼、网格变形、绘画、粒子系统或自动装备规则。每个资产在当前参考组合中有一个可编辑实例；不同摆放用适配配置切换。原图艺术质量、全体型兼容和新动作审美仍需用户目视评审。

## 人物整体摆放与批量选择（2026-09-23）

场景层上方的 **人物整体 · 棋格内摆放** 编辑全局基础偏移。右侧 Y 增大向下；移动工具可在画布拖动，方向键微移，Shift 为 10 倍，Esc 取消拖动。一次拖动一次撤销。包含底座、隐藏部件、备用外观及随后加入的资产；锁定只保护局部校准，不阻止整体坐标系平移。此项跨适配共用，不是视图平移，也不会自动装备资产。动作模式禁止修改此基础偏移，请退出动作模式后调整。

多选的 **画布移动 ΔX／ΔY** 与鼠标共用世界坐标位移：父子同时选择只移动一次，旋转／缩放父级下的子件转换回自身父空间。**设为统一局部值** 则明确将局部参数设为相同数值。选择整个装配包含参考组合中被遮挡、手动隐藏的部件，排除锁定部件；普通框选仅选露出轮廓，穿透框选忽略前景遮挡，仍遵守编辑隐藏、锁定、透明像素和显示裁切。

保存字段 `game.placement: [x,y]`，旧工程缺省 `[0,0]`，无需改写用户原稿。运行时和独立资产绘制都应用一次整体偏移，发布差异包含该字段。CLI 事务示例：`[{"section":"game","id":"placement","value":[0,6]}]`。独立绘制的 `origin` 是调用方棋格原点，不能再手动重复加上 placement。

显示遮罩 `follow` 缺省 `assembly`（跟随人物整体），`grid` 固定棋格，其他值为跟随资产 ID。遮罩坐标属于该跟随对象的局部空间；切换归属后需在该空间校准。图集源图区域始终使用图片坐标，不随摆放改变。引用其他资产轮廓的遮罩仍随其实际轮廓移动。

动作位移／旋转／缩放先在局部取样，再进行附着，最外层统一施加整体平移。具名锚点局部值、关键帧、事件时间均保持不变。外部传入 anchors 是已经包含摆放的世界坐标，内部剥离并重施整体偏移，避免双加；箭矢及预览目标在同一人物坐标系内取样，然后整体移动一次。整体偏移不参与战斗命中或伤害结算。

## 资产评审、批量替换与高分辨率界面

窗口顶部“界面”可选择自动 DPI 或 100%–250% 手动倍率。手动选择存在本机 `user://asset-workbench-ui.cfg`，与具体资产工程分开；资产库和属性栏可各自滚动，顶部工具在窄窗口换行。

资产库和场景层在未处理的名称后显示 `[未处理]`，存疑的名称后显示 `[存疑]`。选中一件或多件资产，在属性栏勾选“已处理”或“存疑 · 稍后复看”。两种状态可同时存在；加入组合、随机查看、保存和发布都不会自动把资产标为已处理。资产库下拉可筛选未处理、存疑、两者合并或已处理；原有分类和文字标签筛选仍可叠加。旧工程中的资产默认未处理，直到用户明确标记。

“装入待处理／存疑”对当前参考组合的每个位置寻找未处理或存疑的同功能槽资产，优先选存疑项；找不到候选就保留原位。“随机装配”每次从同槽其他资产选择；两者都避开组合内重复项、跳过锁定的场景资产，并把仍在组合中的子件连接到所选父件。若某候选导致无效的父级或锚点引用，跳过它继续寻找。一次点击可一次撤销。它们只更改当前参考组合和必要的附着引用，不会改游戏规则或自动发布，随机使用独立随机源。

功能槽比资产库的大分类更细：脸只换脸，发型只换发型；内衣、绗缝衣、外甲、盾、剑、斧、矛、弓和伤损类型也各自分开。现有基础库 ID 自动识别；导入新图片时可填“功能槽”，之后也能在属性栏修改。不同功能槽不会互换。资产的可选 `slot` 为编辑属性；可选 `flip_h: true` 在属性栏显示为“水平翻转”，仅翻图像，不移动位置、枢轴、附着锚点。旧资产缺少该字段时默认不翻转。评审状态存于 `editor.review[id] = {"handled": bool, "flagged": bool}`，仅随草案保存和撤销，不进入游戏发布数据；`slot` 与 `flip_h` 属于资产定义并参与发布差异。

## 按具体组件类型快速对齐（2026-09-24）

资产库下方的「快速对齐…」可以从所选单件或当前参考组合取来源，再按具体 `slot` 找目标。这里的 `slot` 是脸、头发、胡须、身体、各衣甲／头盔层、单手剑、双手剑等细分类；左侧「头面／衣甲／装备」是浏览用大类，不能作为对齐依据。旧 ID 的 `sword` 代表现有单手剑；新双手剑请使用 `sword_2h`，第二层头盔可填 `helmet_layer2`。新类型在导入或属性栏填写一致的 `slot` 后即可互相匹配。

目标可筛选全部同类、未处理、存疑、未处理／存疑，并叠加「只看未分组」；列表支持全选、全不选、逐项勾选或只选高亮一件。组合里同类型有两件来源时须明确选择。预设提供「仅位置」「位置＋等比尺寸＋角度」「蓝框完全一致」；最后一项可能拉伸宽高比。弹窗显示来源、原目标、对齐后三色叠图与变更／跳过数量。对齐只写当前默认值或当前具名适配，一次撤销；保留原图、裁切、枢轴、附着、遮罩、层序、动作和评审标记。它不自动保存草案或应用到游戏。完整行为与验收见 [32](32-asset-batch-alignment-proposal.md)。

若摘要显示「预计修改 0 件」，确认按钮会禁用，并说明蓝框参数已一致或列出跳过原因。本批基础库以 `mail` 为单件来源时，`outer_01`–`outer_04`（含硬化皮甲 `outer_03`）已有相同蓝框。只勾选一件目标后，可在预览里拖动蓝框调整位置，拖动右下角方块等比缩放；「重置预览手调」撤回此次手调。预览操作在确认前不改草案，确认后仍可一次撤销。若蓝框一致但图像轮廓不齐，需检查透明边距和单件裁图。
