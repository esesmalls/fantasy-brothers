# PTR 调研：有方向的构筑与可解释的联动

核对日期：2026-09-17。桌面资料调研，未运行模组或进行版本源码审计。本文区分作者资料与本项目原创建议；采用规则以 [系统扩展设计](../04-systems-expansion.md) 为准。

## 1. 参考对象与版本边界

用户所说 PTR 对应 Legends Perk Trees Rework，由 PTR Team 制作、LordMidasTM 发布。作者页显示版本 2.2.2、2023-12-19 更新，并说明停止支持，转向 Reforged。两者不能视为同一套规则。[作者发布页](https://www.nexusmods.com/battlebrothers/mods/438)

作者说明的核心机制之一是技能树加权分配：出身与已有树影响后续分配，使角色有主题也有变化。作者仓库 README 与发布页的技能数量不同，本项目不据此设规模目标，也不把仓库内容直接等同最终发行版。[作者仓库](https://github.com/LordMidas/LegendsPerkTreeRework)

历史更新记录提供具体联动例子：1.6.12 的 Shields Up 涉及邻近持盾队友的盾墙及失效条件；Pattern Recognition 在与同一对手交锋时逐步获得优势，数值曾反复修订。旧版本的免费追击与多段攻击还出现过死亡、连锁触发相关修复。这些用于理解设计与维护成本，不宣称是最新版本的完整技能说明。[作者更新记录](https://www.nexusmods.com/battlebrothers/mods/438?tab=docs)

Battle Brothers 原开发者谈过专长设计应支持不同策略、避免破坏基本机制。本项目采纳这一评价标准，而非照搬当年的技能数量和树结构。[开发者技能设计日志](https://battlebrothersgame.com/dev-blog-80-progress-update-new-perk-system/)

## 2. 对本项目最有价值的启发

以下是设计推断，不是 PTR 的功能清单：

1. **基础方向可规划。** 武器与出身提供稳定岗位，随机成长提供变体；玩家需要能计划前排、输出与救援。
2. **技能改变决策。** 联动应改变站位、顺序、目标或资源取舍，而不只是累计百分比。
3. **队员彼此创造机会。** 条件制造者与利用者可以是不同人物，让队伍构筑比单体堆叠更重要。
4. **随机要有适配与回退。** 先检查前置、装备、互斥与已有能力，再加权；关键组件存在训练或任务渠道。
5. **复杂度进入验证成本。** 多段、反击、死亡和免费动作会相互作用，需要明确触发来源与次数。

## 3. 三组原创联动试验

| 构筑 | 配合 | 成本、反制与范围 |
| --- | --- | --- |
| 盾兵破阵—长枪利用 | 盾击制造可见破绽，长枪指定攻击消耗破绽，取得一种收益 | 两人行动与站位成本；后撤、换线或压制枪手可以打断。前 12 周验证 |
| 驯兽标记—战犬牵制—猎手射击 | 标记指定猎物，战犬占据威胁位置，猎手利用射击窗口 | 战犬占名额、补给并承担伤亡；护卫、重甲和威胁驯兽师能反制。独立实验后接入 |
| 布油—点火—浇水遮蔽 | 物件与工具封路，蒸汽改变双方射击路线 | 消耗物资与行动，也可能伤及友军或粮仓；绕行、灭火或近战接近可以反制。先做两条反应 |

采用少量共享状态：破绽、标记，以及后续湿润。武器、人物经历与团路线调用同一状态，避免每项能力创造独占资源。通常提供基础、联动、拓展三类合法成长选项，池不足使用有限通用训练；仍不足显示实际候选数。

## 4. 原型验证与淘汰标准

每组安排适合发挥、有反制、其他打法也有效的三种场景。观察玩家能否在行动前说明触发条件，是否愿意为机会付出行动点，以及另一名队员是否有参与价值。

规则验证覆盖未命中、目标／来源死亡、多段、反击、派生伤害、存读档和跳过动画。默认同一被动在同一根行动对同一目标至多触发一次；派生伤害不再触发直接命中专长。限制触发次数不能代替修复错误或解释规则。

若联动总是无代价更强，增加机会成本或反制；若只是多按两个按钮，改变它解决的问题；若必须抽到稀有能力才可用，补上稳定获得途径。免费回合与无限资源返还不进入早期范围。
