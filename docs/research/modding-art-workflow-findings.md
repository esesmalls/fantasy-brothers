# Battle Brothers 模组与社区：人物资产制作经验

调研日期：2026-09-20。主AI独立完成，无子智能体。本轮只研究和记录，不改变U48资产、尺寸、动作或战役规则。

## 结论

现有H静态半身路线适合继续推进。最值得补强的是共同装配样板、装备兼容记录、实际小尺寸修整与成套状态验收。社区资料能支持这些制作方法，不能证明当前样板已经合格，也没有提供能直接替换现有工程的完整人体换装动画方案。

优先把下一轮评审做成可重复使用的“试衣与校准工作台”，再扩大资产数量。这是本次建议，尚未实施。

## 查到的直接依据

### 1. 位置和显示尺寸应有明确记录

社区《Brushes》教程区分源图片和游戏显示范围；`left/right/top/bottom` 定义相对位置及显示大小。教程推荐用Paperdoll校准，再保存元数据；角色面板与战场单位的原点不同，不能直接套同一偏移。[社区教程](https://bbmodding.enduriel.com/docs/concepts/brushes/)

Paperdoll的页面源码说明支持网格定位、拖动/方向键、透明度、层序、组合及复制坐标。已阅读公开说明和页面源码，未完成在线工具实际操作；网页抓取失败不代表工具不可用。[作者仓库](https://github.com/MSUTeam/paperdoll)、[页面源码](https://github.com/MSUTeam/paperdoll/blob/main/index.html)

**用于我们：** 固定底座中心、盘面前弧、肩线、领口、下颌和武器支点；同一身份/装备状态共用定位。统一的是这套装配坐标，不要求所有源PNG拥有相同外框。现有catalog已经记录部分信息，下一步可增加可视化叠底校准，减少凭文字反复生成。

### 2. 套层需要兼容设计与逐组试穿

Paul说明，做护甲附件时调整过一些护甲的位置，以改善组合；头盔轮廓差异大，相同附件并不能自然适配所有盔型。该页也说明视觉叠加与玩法限制共同影响了原版附件设计。[Paul，第99页](https://battlebrothersgame.com/forums/topic/pauls-art-corner/page/99/)

Legends构建文档把层级、外观变体、可叠加基础及发须隐藏字段写入定义，并检查装备图标文件。[Legends作者文档](https://github.com/Battle-Brothers-Legends/Legends-public/blob/development/documentation/how_to_build_legends.md)

**用于我们：** 玩家自由换装的目标保留，生产侧需为不同领型/盔型做适配变体或遮挡规则。同一甲损状态不应换肩宽、领口或花纹；隐藏发须应来自明确兼容设置。不能把“每个PNG都能叠上去”当成自由穿戴已成立。不要从原版“一件附件”推导出我们也必须限制为一层甲。

### 3. 画得精细与战场上看得清是两项工作

Paul向模组作者解释过：源图缩小后还会修整；可以适量调整边缘、亮度、锐度、对比度和金属色调。他特别指出，大画幅的密集细节缩小后可能产生噪杂感。[Paul，第115页](https://battlebrothersgame.com/forums/topic/pauls-art-corner/page/115/)

另一组答复建议减少尖碎细节、保持较清楚的表面，并用边线区分人物不同部分；提供了图标制作流程和过量细节的处理示意。[Paul，第117页](https://battlebrothersgame.com/forums/topic/pauls-art-corner/page/117/)

**用于我们：** H的细致面容和材质保留，1×战场尺寸先看眉眼、鼻梁、胡须块面、领口与武器刃形。链环/绗缝应有疏密和明暗分组，避免每个细节都一样尖亮。大图审材质，1×审识别，两个尺度都通过才入库。描边和明暗要局部、有轻重；不自动给所有图套厚黑边或强锐化，也不用程序噪点制造磨损。

### 4. 先在目标场景中试装，再导出

Paul在展示女巫资产时说明，会先在模拟场景中调整、检查，再导出成品。[Paul，第92页](https://battlebrothersgame.com/forums/topic/pauls-art-corner/page/92/)

**用于我们：** 保留当前导出包和网页回放，再加同一镜头下的多装备/多脸组合，检查草地、泥地、暗地和相邻单位遮挡。当前单人绿底与放大总览不足以代替真实战场观感。穿戴、伤损、倒伏需要保持同一身份和装备连续性；倒地不能提前等同确认死亡。

### 5. 一个很贴题的新工具，但目前只作方法参考

Nexus的BB modding center（作者Dream5unit，页面标记2026-07-28更新）介绍MC Paperdoll Tool：参考框对齐、叠图试穿、1×/2×/3×预览、模板导出，以及透明背景、轮廓越界和倒伏配对检查。作者同时说明完整头/身/尸体套件流程仍有未完成部分，运行产物依赖Legends框架。以上仅为作者声明，本轮未下载安装或实测。[作者页面](https://www.nexusmods.com/battlebrothers/mods/1091)

**用于我们：** 借鉴其检查项目和交互布局即可；现有Godot评审器已能显示实际装配和动作，继续扩它更能保持表现一致。自动拆头身、自动对齐不能直接当成质量保证。

## 对当前U48的具体判断

| 项目 | 已有基础 | 建议补强 |
| --- | --- | --- |
| 底座与截取 | 底座固定、组右移、依据原画盘面前弧裁取 | 固定参考叠图和可视锚点；衣甲本身仍需同向肩胸结构，裁边不能修正错误透视 |
| 头与领口 | 头独立、低落、正常/伤脸共锚点 | 不同脸型与不同领口的组合图；检查耳后、下颌和后领遮挡 |
| 两层护甲 | 一体型、配套绗缝/链甲及甲损 | 建立真正的跨组合检查；当前破口内衬颜色画在甲里，不应宣称任意内衬颜色已兼容 |
| 小尺寸效果 | 回放有1×小窗 | 增加1×静态横向比较；精细纹理让位于身份、材质与武器轮廓 |
| 武器 | 剑/枪/弓分别定义姿态和轨迹 | 同类武器共享支点标准，按长度/刃形少量修正；战场图与背包图分别验收 |
| 状态 | 脸伤和甲损可独立切换 | 后续新增装备时将完好、破损、倒伏和对应图标视为完整交付，而非只验站立图 |

表内后两列的判断来自当前工程和本次分析，不是外部作者对本项目的评价。

## 建议的下一小步与成本

1. 在现有评审器增加装配校准视图：锁底座、轮廓叠底、显示/隐藏层、锚点和1×/2×并排。先验证当前资产；不生成一批新衣服。
2. 选少量既有面容与两套甲做组合检查，标出具体哪一层、哪个区域不合身。发现领型差异时做适配图，不依靠非等比拉伸。
3. 只重绘失败的部位/状态，保留用户认可的面容、材质和动作；生成后重新核对实际装配。
4. 通过一套完整样板后，将部件定位、兼容记录和验收截图随资产存档，再继续扩量。

这把可重复的校准交给工具，把生成成本集中到需要美术判断的修订。没有在本轮批准新的资产数量、采购费用或制作周期。

## 工具选用与证据边界

- **MSUTeam Paperdoll：** 适合学习坐标校准工作流，也可将来作为BB侧参考检查。我们仍用Godot评审器保存本项目的坐标/裁取数据，不直接照搬其偏移数值。
- **BBBuilder / bbrusher：** 前者自动化BB模组构建并调用后者处理brush；适合BB格式整理，不能改善人物绘画质量，也不是Godot运行依赖。本轮只读作者说明，未安装。[BBBuilder作者仓库](https://github.com/TaroEld/BBbuilder)
- **MC Paperdoll：** 上述功能尚未经本机验证，不建议现在把整个资产生产迁过去。
- **Spine/三维降二维：** 本轮未发现能直接接上我们现有散件、又自然处理所有换装动作的成熟整套方案；保持用户选定的静态身体＋武器反馈。

本次公开资料没有证明Battle Brothers内部采用“运行时椭圆遮罩裁衣”的相同算法；U48的前弧裁取是我们根据用户构图要求采用的实现。也不把文档中某个战场偏移值当成普适画布规格。

查阅范围为公开社区教程、作者仓库说明/页面源码、Nexus作者说明和官方美术师的论坛答复。Reddit、Steam讨论用于检索线索，未作为关键技术结论。未读取Discord内部教程；未解包本机参考游戏；未导入第三方资产/程序。GitHub树API遇到限流，未声称完成Legends源码审计。部分旧论坛链接抓取不稳定，报告只采用已读到的内容。

## 验证

仅文档增量，无运行资产/脚本变更，无需重跑游戏测试。来源与项目建议分开记录，链接和本地导航检查后随当前动作分支同步。用户尚未因此批准新的工具安装或全库量产。
