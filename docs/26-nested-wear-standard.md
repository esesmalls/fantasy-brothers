# 衣甲嵌套与内层露出

2026-09-21 · U50。用户指出：穿戴要表现外衣包裹内衣，领口、缺口与破损处应看到实际穿着的内层；现有整张图上下覆盖不足以成立。

## 采用的视觉规则

1. **一件资产只画属于自己的材料。** 领口暗腔、破洞不能用固定黑色或预画衬甲填满。绗缝自己的填充物可以留在破口边缘，下面的亚麻必须来自实际亚麻层。
2. **按共同身体和视角设计包裹形状。** 领边、肩胸和近远侧方向沿用同一H模板；外层领口需要给内层领口／胸前布料留出实际可见空间。不能单靠放大整件衣服，也不能让多件衣物共用完全相同的领口高度，最后互相盖死。
3. **开口有透明中心和属于外衣的实体边缘。** 前领边遮挡内衣，边缘厚度、缝线、金属环和局部阴影由原画表现。相交领片或更复杂护肩将按需要拆为后部／主体／前缘，当前这组简单开口由正确的透明形状即可表达，不额外添加程序肩领盖缝。
4. **沿可见方向显示最近的实际内层。** 链甲缺口下有绗缝就显示绗缝；撤掉绗缝则显示亚麻，再撤掉亚麻则显示基础内衣。所有内层都撤掉，开口透出后方。完整外壳仍遮住内层，不把整个甲半透明化。
5. **外甲损坏不自动证明内甲损坏。** 每一层有各自的视觉完好／破损状态。未来战斗伤害如何传到内层由规则决定，不能由贴图替玩家决定。

当前身体仍是基础内衣，尚非裸胸；没有内衣时的皮肤、伤痕不能直接挪用黑色领腔。身材、厚度或领型不兼容时制作适配原画，不能用非等比拉伸补救。

## 本轮实际修复

查明旧 `full-garments.png` 的亚麻V领是实色暗面；绗缝与链甲的领腔、部分甲损破口也预画了固定衬料。渲染层序虽然存在，实际内层无法透出。U48／49“配套图层可以显示”不能再视为真实穿衣嵌套已经验收。

本轮用内置imagegen编辑两张1254×1254 RGBA图集：`full-garments-nested.png` 与 `full-damaged-nested.png`。使用其中三种外衣的正常图、两种护甲的破损图；基础内衣继续引用旧原图，未采用生成图中多余的基础内衣变动。领口及破口中心有真实alpha，源图不经程序重画、抠色或补边。

固定底座、前半圆截取、头身比例、武器和所有部件的矩形／尺寸／位置／锚点与v3保持相同。旧原画及 `catalog-v3.json` 留作对照，当前目录改为U50新图集。完整长袖衣甲仍保存；棋子显示依旧按固定盘面窗口截取。

真实渲染检查验证：同件亚麻撤下基础内衣后V领透空；同件破损链甲换内层时金色绗缝／灰色亚麻随实际层变化；绗缝破口也能换成灰色亚麻／棕色内衣；外衣非开口处保持不透明。见[直接切换内层的对照](../art/validation/2026-09-21-nested-wear/index.html)。这是一套已有衣甲的验证，不等于所有未来装备都已自由适配。

## 工作台与数据

- “内外层检查”固定显示旧领口、新领口及移除内层的比较；下排只损坏链甲。此视图特意隐藏头、武器和底座，避免底座盘面在后方被误认为固定衬料。
- 装配视图仍可逐层开关。勾选“甲损”后，可选“损外层／损衬甲／全损”；这些为临时检查状态，不写入定位草案或候选目录。
- 渲染支持可选 `wear_damage` 字典，按 `padded / mail` 指定视觉损伤；未传时保留旧调用的整体损伤参数兼容。本轮没有修改战役的装备槽、耐久、伤害或存档规则。
- v3参考图继续使用原目录。当前数据和原v3全部几何字段相同，因此只对白名单内的v3目录摘要接受旧草案；载入后保留用户位移，标示新衣甲需复看并重新保存。原草案不自动改写，保存仍保留 `.bak`。
- 索引脚本先比较v3的源矩形、尺寸、位置、锚点和裁取，再决定是否允许旧草案；将来这些字段改变时，不自动迁移。此检查只保证坐标兼容，不能代替对新原画的复评。
- 目录输出统一LF；兼容历史v3的Git LF与本机CRLF两种摘要，防止三台电脑仅因换行不同而拒绝同版定位草案。

## 后续衣甲验收

每一件新增外衣至少配两种真实内层查看领口／前襟，并覆盖正常、仅外层损坏和移除内层三种状态。切掉头部单看衣服、完整人物看领口，以及1×／2×小尺寸都要复看。透明开口边缘应保留材质厚度；若前后遮挡关系不能靠一个壳层表达，再制作前后片，而非继续堆实色盖缝。

领型、体型、披肩、兜帽与头盔兼容尚需后续小样。没有新增裸身、六向、骨骼或物理布料方案，继续按用户指定的H静态半身＋独立武器反馈路线。
