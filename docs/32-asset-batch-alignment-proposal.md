# 资产装配器：按具体组件类型批量对齐

2026-09-24。用户已批准单件或参考组合批量对齐，并明确要求按脸、头发、胡须、身体、各衣甲／头盔层、单手剑、双手剑等**具体组件类型**匹配。本功能已接入当前资产表现编辑器；打开工程不会自动改动任何素材。

## 为什么需要

当前 `Paperdoll.cmd` 使用 schema 5 资产表现编辑器。基础库工程已经有大量同功能槽的替换素材；用户调好一套参考组合后，逐件重填位置、显示尺寸和角度很耗时。现有多选「设为统一局部值」只改当前选中的资产，不能从参考组合按功能槽找到整个资产库中的候选。旧纸娃娃工作台的「对齐参数」也不是这项跨资产库操作。

蓝色选框表示部件在棋格上的显示范围，并不保证图片的不透明轮廓恰好贴着框。因此「对齐选框」是批量初校，完成后仍要查看面部、衣领、盾缘与武器接触的位置。

## 使用方法

在资产库或场景层选中一个已校准部件，点击 **快速对齐…**。弹窗显示来源、具体组件类型和当前编辑范围（默认参数或具名适配）。来源也可切为 **当前参考组合**；组合中的每个具体类型各取一件来源，按类型分别处理。组合里若有两个同类型来源，必须先选一个，不能暗中用最后一件。

目标列表先取与来源**同功能槽**的资产，排除来源本身与锁定资产，再按用户所选范围过滤：

- 全部同槽；未处理；存疑；未分组；手动勾选若干件。
- 未处理与存疑是可重叠的评审状态。两者同时勾选时取并集；再与「未分组」等条件取交集。未分组指没有出现在任何 `editor.groups` 中，不表示没有资产分类或功能槽。
- 弹窗逐类型列出候选 ID、现有状态与最终数量。可以全选、全不选、逐项勾选，或点中一件后使用「只选高亮一件」。最终以弹窗勾选的 ID 为准，防止隐藏的候选被意外修改。

当前 `foundation-review.asset.json` 有 92 件资产，`editor.groups` 为空，所以在这个工程里「未分组」暂时等同于全部候选；待用户建立编辑分组后才会缩小范围。评审筛选目前更有实际区分度。

具体类型使用现有 `slot` 字段，旧素材仅对已知 ID 作兼容推断，**不能**只按「头面／衣甲／装备」大分类匹配。当前旧素材的 `sword` 槽表示单手剑；明确命名的 `sword_2h`／`greatsword` 进入双手剑槽。新头盔等类型请在导入或属性栏填写稳定的 `slot`，例如 `helmet_layer2`。未知 ID 不会因为同属「装备」而自动配对。

## 可复制的内容

弹窗提供三个预设，而不是为每一种属性放一个常驻按钮：

| 预设 | 行为 | 用途 |
| --- | --- | --- |
| 仅位置 | 使目标显示框中心与来源位于棋格同一位置，保留目标大小与角度 | 素材尺寸已正确，只需摆放 |
| 位置＋等比尺寸＋角度（默认） | 匹配来源的棋格位置和朝向，在来源显示框内等比缩放目标 | 同槽素材的快速初校 |
| 蓝框完全一致 | 匹配来源显示框的宽、高、位置与角度；若宽高比不同，预览提示可能拉伸 | 来源和目标确实使用同一画布规格 |

计算对齐时使用棋格中心的世界坐标和实际显示框，不直接复制局部 `position` 数值。父资产旋转或缩放时，要反算目标的局部位置；已经附着的资产保留自己的父资产和锚点。显示尺寸应由 `size` 与 `scale` 的最终效果计算，避免复制相同缩放值却得到不同大小。

若只勾选一件目标，预览中的蓝框可以直接拖动来调整位置，右下角蓝色方块可等比缩放目标；金色来源和灰色原目标保持原位供比较。「重置预览手调」恢复所选预设的结果。手调仍通过同一套父级附着换算和校验，只在点击确认后写入草案；若后来改选来源、筛选或预设，先前的预览手调会清除。

默认保留每件素材自己的图片、源图区域 `rect`、枢轴 `pivot`、父资产与锚点、遮罩、水平翻转、绘制层、动作轨道、来源和评审状态。这些属性各有独立的创作含义，不宜随选框一起覆盖。若以后发现同槽素材确实需要统一绘制层或枢轴，可在高级选项单独加入，并独立预览影响。

## 执行与安全边界

点击前显示每个类型的来源、将修改的目标数、预计变化的属性和跳过原因。预览对当前高亮目标叠放来源（金色）、原目标（灰色）和对齐后目标（蓝色）；提交后还应在主画布检查它与衣领、武器、底座等邻件的实际效果。锁定、类型不符或无法无损表达的几何变换会跳过并说明原因；若整体数据校验失败，则拒绝本次提交。

当「预计修改 0 件」时确认按钮禁用，弹窗会在列表上方说明原因。本批基础库以 `mail` 为单件来源时，四件 `outer_01`–`outer_04`（包括硬化皮甲）已经有相同的显示框位置、尺寸与角度，所以批量复制无需写入。若素材轮廓仍未贴齐，可以单选目标在预览中手调蓝框；透明区域或裁切本身仍需在单件编辑中处理。

一次确认形成一笔可撤销事务。默认参数下仅更新资产默认值；处于具名适配时仅写该适配的覆盖值，弹窗明确显示写入范围。操作不自动标记「已处理」，不修改参考组合成员，不保存草案，也不应用到游戏；用户检查后再分别保存和应用。

`my_test-v2.json` 是旧 schema 3 校准，不是完整资产库清单。现有 `current.asset.json` 已从它迁移，可直接作为当前工程的参考来源。跨工程直接选择旧 JSON 作模板涉及迁移、同槽映射与图片来源校验，建议在同工程操作稳定后单独设计。
