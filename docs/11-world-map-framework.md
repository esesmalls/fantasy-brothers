# 大地图最小闭环 · 0.1.3

更新：2026-09-19。用户在试玩认可0.1.2后，明确授权接通“旅行—事件—契约战斗—返营生活”。本轮用现有两团、两路线、六事件和粮仓战场实现，不扩充故事数量或战斗规则。测试与导出记录见 [08-validation.md](08-validation.md)。

## 已实现的玩家循环

`地图中的灰岸营地 → 比较两路并接约 → 逐站旅行 → 已保存途中事件 → 继续行军 → 粮仓准备 → 战斗 → 清点/成长 → 准备返营 → 营地生活 → 再接约`。

开局进入边境地图，显示当前旗帜、已发现地点、契约目的地和行程。点击地点只浏览详情；只有明确的“接约出发”“继续行军”“返回营地”按钮改变旅程。营地生活单独展示队员、团志、休养、口粮、修甲和补员。地图可以查看粮仓上次契约结果。

新旅行按地点推进，事件在接约时生成并保存，到指定节点才显现。选择后回到行军；粮仓外补给事件发生在终点，选完直接进入准备。第三次钟声事件真正到裂钟桥头处理，之后继续粮仓契约。旧版正在进行的事件保留原来的事件→准备衔接，不强迫补走新地图。

## 成本、风险与失败恢复

去程沿用已验证代价：旧道2粮/1天，险径3粮/1天，出发时仅扣一次；逐站点击不追加粮食或天数。险径敌情+1（上限2）、基础报酬+18金、多1油，封顶后仍显示实际敌情。事件成本单独列出并在选择时兑现。合同为固定粮仓报价，地图浏览不随机报价。

战斗清点沿用原有额外1天，显式返营不再扣天数、粮食或再次发奖。胜利兑现报酬、护仓奖励及成长，撤退按既有战利品结算、无完整合同报酬，败北保留损失。永久死亡不复活。资金/口粮为零或全员死亡也不阻断返营；随后使用短工、缓慢休养/修甲、预支补员恢复，不能靠打开地图或重复返营刷收益。

## 实际接口与边界

- `world_data.gd`：固定地点、归一化坐标、八条连线与两路基本路径；原创内容，不依赖外部地图资产。
- `Campaign.get_world_view(c)`：纯读地点/发现、当前位置、已保存路径与步数、下一站和报告。
- `get_contract_offers(c, location_id)`：纯读固定粮仓合同与路线报价，接约校验仍由规则执行。
- `accept_contract(c, contract_id, route_id)`：验证位置、阶段、活人、粮食和无未返营合同，之后一次扣费并生成事件和旅行。`start_expedition` 为同一入口的别名。
- `advance_travel(c)`：推进一处已保存节点，不扣费、不重抽；进入事件或准备阶段。
- `choose_event(c, choice_id)`：核对事件实例、阶段、选项与成本，成功后保存已选实例，继续行军或准备。
- `begin_battle(c, battle)`：验证远征与行程状态，原子进入战斗；`battle_config` 带合同/旅行/地点 ID。战斗规则仍为 prototype-0.1.1。
- `resolve_battle`：既有奖励/伤亡/债务结算，保存粮仓结果，然后成长或 returning；`choose_growth` 后进入 returning。
- `return_to_camp(c)`：仅已结算且等待返营时执行一次，位置回营、清理活动行程，进入 camp；不再发奖励或额外扣费。

变更函数沿用 `{ok, reason}`。非法、重复、阶段错误或资源不足的操作在变更前拒绝。地图画布 `world_map.gd` 与组合界面 `world_screen.gd` 不结算规则；动画或点击地点不改变游戏状态。

## 存档、实例与兼容

战役外层schema和包络格式仍为1；新增 `world.schema=1`、`content_version=world-0.1`。world保存当前位置、已发现地点、活动合同、旅行、地点结果和已解决事件实例。旅行保存稳定ID、路线节点、边、当前索引、事件节点、一次性代价及状态。世界规则不保存坐标副本，UI从固定数据读取坐标。

`travel.id` 使用原远征 ID。合同奖励的唯一权威仍为 `campaign.claimed[expedition_id]`，事件通过 `<expedition_id>:<event_id>` 与 `resolved_event_instance_ids` 防重复；两者不混作两套合同领取键。`pending_effects` 仅为空的预留字段，本轮没有通用延迟效果调度器。

旧档先经过完整校验再迁移，不重抽、不补扣代价，也不改变正在进行的 event/ready/battle/growth 阶段；迁移后再次校验。旧camp映射营地，旧事件按原准备路径继续，已有成长候选保留。新世界状态检查位置、路径、索引、阶段、实例和领取记录的一致性。主档损坏继续使用既有完整备份恢复。

三台电脑应统一使用0.1.3继续新进度；源码同步不传个人档。旧版程序不理解新旅行阶段，勿用它覆盖已经接入地图的进度。迁移自动回归使用构造旧状态，不能冒充已检查每台电脑的个人存档。
