# 大地图最小骨架与接入计划

更新：2026-09-19。本文是下一增量的实施设计，**不是** 0.1.2 已实现功能。它将现有营地、两条路线、六个事件和粮仓战斗放到一张小型边境图，验证佣兵团如何旅行、生活与接活；不扩写世界史，不加入士气、疲劳或新的战斗规则。

## 范围与依据

| 类别 | 内容 |
| --- | --- |
| 已实现（0.1.1） | `camp → event → ready → battle → growth/camp`；营地休养、补给、修甲、补员及缺钱恢复；渡口旧道/山脊险径；六个生成即保存的事件；粮仓战斗、死亡、撤退、成长和以远征 ID 防重的结算。两条路线目前复用粮仓。 |
| 用户已确认 | 战役内持续成长；旅行、肉鸽事件、战斗、契约结果与伤亡损失要构成循环。 |
| 本文采用范围 | 下一增量交付固定地点、有限连线、一个可接的粮仓契约和返营恢复。现有六事件只做地点化，仍处于原故事额度。 |
| 提案 | 地点名、边数、行程天数、口粮和冷却为可试玩数值，未定为最终平衡。 |

设计借鉴项目既有调研中的条件筛选、生成后保存与失败恢复原则；地点、人物、钟声和选项文本均为本项目原创。没有导入外部游戏文本、代码或素材。

## 玩家闭环

```mermaid
flowchart LR
    A[灰岸营地：生活与整备] --> B[边境图：路线与契约]
    B --> C[接雨夜粮仓契约]
    C --> D[旅行：口粮/天数/已保存事件]
    D --> E[粮仓战斗]
    E --> F[一次结算：报酬、物资、伤亡、地点后果]
    F --> A
```

营地显示公司位置、活人、金币、口粮、日期和可接契约。接约前路线卡列出天数、口粮、风险、报酬和工具；无法出发必须说明原因。旅行进入已确定的节点，事件选择后进入原战斗准备。胜利、撤退和失败都回营：伤亡、护甲和生命损耗保留，未完成契约不发全额报酬，短工、休养、修甲和预支补员仍可恢复。

两团的代价也保持真实：自由团可稳定走低耗旧道；猎团可在足迹事件免费侦察，但战犬占四个出战位、同样吃口粮且死亡必须补员。UI 不显示当前规则未结算的士气、疲劳或团结度。

## 固定地点与路线（提案）

地图候选为六点、八条无向边；不做随机地形、自由拖拽行军、战争迷雾或地图战斗。

| 稳定 ID | 地点与用途 | 初始可见 | 相邻地点（无向；不单独扣费） | 失败后用途 |
| --- | --- | --- | --- | --- |
| `loc_greyshore_camp` | 灰岸营地：休养、补给、修甲、补员、名册 | 是，公司起点 | 渡口、林边、山脊 | 所有结算回此；恢复通路一直开放 |
| `loc_ferry_crossing` | 渡口：旧道、粮仓契约 | 是 | 营地；桥头；粮仓 | 可做现有短工换粮 |
| `loc_ridge_pass` | 碎石山脊：险径入口 | 是 | 营地；桥头；林边 | 可回营，不锁死 |
| `loc_hunter_edge` | 林边：足迹事件 | 首次经过后 | 营地；山脊；粮仓 | 猎人死亡时普通队员可慢速侦察 |
| `loc_granary` | 雨夜粮仓：当前唯一战斗契约 | 接约后 | 渡口；林边 | 存毁记录后返营 |
| `loc_bridgehead` | 桥头：第三次远征裂钟收束 | 第三次接约后 | 渡口；山脊 | 钟的去向不封锁回程 |

下一增量只实现两条聚合行程：`road` 1 天/2 粮、`ridge` 1 天/3 粮，在确认出发时扣费一次。中间地点作为已保存的行程与事件节点，推进节点不重复扣费。上述八条连线用于后续扩展，尚不承诺全部可以自由旅行；自由选边、逐边扣费与平衡调整另做增量。

## 数据与接口计划

继续使用 JSON-safe 战役状态、整数 RNG 和 `campaign.schema=1`。迁移必须补齐新字段，不能删除旧 `route_id`、`event`、`claimed`、`history` 或远征字段。

```text
world = {
  schema: 1, content_version: "world-0.1",
  company_location_id: "loc_greyshore_camp",
  discovered_location_ids: ["loc_greyshore_camp", "loc_ferry_crossing", "loc_ridge_pass"],
  active_contract_id: "" | "contract_rain_granary",
  travel: {}, location_states: { location_id: { flags: {}, last_visit_day: 0 } },
  pending_effects: [], resolved_event_instance_ids: []
}
```

`travel` 最小字段：`{id, contract_id, origin_id, destination_id, route_id, edge_ids, current_edge_index, food_cost, days, event_instance_id, status}`。首版 `travel.id` 直接复用既有 `exp_<seed>_<index>` 远征 ID，合同结算继续只由 `campaign.claimed[expedition_id]` 防重，不再另建一套领取键。新事件实例键提案为 `<travel_id>:<event_id>`；显示名不能作为存档键。`edge_ids/current_edge_index` 只描述视觉节点进度，成本在接约出发时一次结算。

现有稳定 ID 包括 `road/ridge`、远征、下表六个 `event_*` 与 choice ID。`loc_*`、合同 ID、world 字段、事件实例键、scope/content_version/cooldown 都是尚未落地的新提案；当前事件实例由事件 ID 加远征 ID 的历史记录识别。

| 窄接口 | 职责与兼容方式 |
| --- | --- |
| `get_world_view(c)` | 只读返回地点、发现边、公司位置、可用操作和真实资源；不推进 RNG。营地 UI 是 `loc_greyshore_camp` 的视图。 |
| `get_contract_offers(c, location_id)` | 纯读取/构造固定粮仓报价，不推进 RNG、不写档；由接约接口原子保存选择。未来随机报价另设明确的生成接口。 |
| `accept_contract(c, contract_id, route_id)` | 校验位置、存活队员、口粮和无未结算行程；一次扣聚合行程代价，创建并保存合同/旅行/事件，复用现有参与者和历史。首版只允许营地接粮仓。 |
| `advance_travel(c)` | 按保存的视觉节点和索引推进，不再次扣费或重抽；已保存事件转 `event`，终点转 `ready`；UI 刷新不得推进。 |
| `battle_config` / `resolve_battle` | 保留当前入口和远征 ID 校验；透传 `contract_id/location_id/travel_id`，以既有 `claimed[expedition_id]` 校验并记录一次奖励，更新旅行与地点后果，再回营。 |
| `camp_action` / `choose_event` / `choose_growth` | 保持现有签名和行为；仅在营地且无未结算旅行时开放生活操作。 |

所有变更接口统一返回 `{ok, reason}`；非法、资源不足、重复操作和已结束旅行均在变更前拒绝，失败不改变 world、资源、RNG、history 或 claim。

可新增 `world/travel/contract` 阶段，但旧档迁移时 `camp` 映射为世界中的营地操作，未结束的 `event/ready/battle/growth` 绝不强制移动。旧 `road/ridge` 映射为聚合路径。存档记录迁移来源，不承诺跨规则版本重放一致。

## 六个既有事件的地点化

不新增第七个故事事件。所有选择先校验成本；选择、事件实例、延迟效果和奖励领取均写稳定 ID。事件仍先检查阶段与选项；新接入时在扣费前核对 `c.event.event_instance_id`，并检查 `world.resolved_event_instance_ids`，选择成功后原子写入已选实例与 ready 阶段。重复事件或 `claimed[expedition_id]` 已结算的契约必须失败且不改资源、成长或地点状态。候选先按地点、契约、活人、flags、资源和近期记录筛选；空池回退为平静行军，仍可进已接契约。

| 事件稳定 ID | 位置/触发/限制 | 缺席或死亡路径 | 选项 | 即时后果 | 延迟后果与测试路径 |
| --- | --- | --- | --- | --- | --- |
| `event_bell_on_bank` | 渡口；首次接粮仓；限1 | 原参与者不在时全团承诺 | `bell_protect` / `bell_contract` | 水+2、报酬-8 / 油+1火+1、报酬+6 | `villagers_promised`；新档→接约→存读档→选择→结算 |
| `event_granary_stores` | 粮仓外；非首程、非第三锚点；不与上次相同，可重复 | 不依赖角色 | `stores_oil` / `stores_water` | 油+2火+1水-1 / 水+3油-1 | 无链；连续远征与存读档验证无重抽和不连续重复 |
| `event_hunter_tracks` | 林边；非锚点；近期加权 | 无猎人时付1粮慢速侦察；无人不得出发 | `tracks_scout` / `tracks_salvage` | 难度-1（猎人免费）/ 油+1金+6 | 无链；猎人死后仍能选择并进入战斗 |
| `event_village_reply` | 渡口至粮仓；曾护仓后的下一非第三锚点；限1 | 原接话者死亡时旗帜与全团接收 | `reply_rations` / `reply_water` | 粮+4 / 水+2、胜利声望+1 | `villagers_repaid`；承诺者死亡→补员→再接约→仅兑现一次 |
| `event_unposted_letter` | 营地外旅行；非锚点、至少一名活人、受冷却 | 参与者缺席时全团处理；无人时不生成 | `letter_share` / `letter_risk` | 粮-1、全员治疗10、报酬-4 / 难度+1、报酬+14 | 无链；参与者前次阵亡后存读档，扣费和选择一致 |
| `event_bell_at_bridge` | 桥头；第三次远征；限1 | 不需指定人物与前次胜利 | `bridge_keep` / `bridge_deliver` | 水+2、声望+2、报酬-12 / 火+2油+1、报酬+10 | `bell_left/delivered`；前两次失败更换队员后仍能在第三次收束 |

## 三种作用域与结算约束

事件数据统一含 `scope: travel | contract | battle` 和 `{id, content_version, trigger, participant_slots, repeat_limit, cooldown, choices, immediate_effects, delayed_effects, absence_path, test_path}`。下一增量只实现 `travel`，并将当前粮仓选择归此类；`contract` 与 `battle` 仅留接口，**本轮不实现战中事件**。

| scope | 窗口 | 当前/后续边界 |
| --- | --- | --- |
| `travel` | 已保存路线边进入、战斗前 | 只改补给、难度、报酬、旗标和承诺；不能重抽 |
| `contract` | 接单、失败/撤退、完成结算 | 后续按地点和契约 ID 改可见地点或恢复机会；不依赖已死亡唯一人物 |
| `battle` | 固定回合/目标/物件条件 | 未实现；必须从战斗规则动作/状态/结算事件接入，预览和动画不得触发随机或扣资源 |

接约只扣预告旅行成本一次；创建旅行后不能重开 UI 换路线。战斗前保存参与者、工具、选择和地点。胜利兑现合同、粮仓存毁、声望和成长；撤退仅带少量现有战利品；失败无合同报酬。三者均写旅行已结算、历史与伤亡并回营，之后一次性应用延迟效果和债务偿还，才开放恢复。第三次短篇仍使用既有 `ending_seen`，不扩展阵营战争或开放世界日程。

## 拆分、验收、依赖与遗留问题

| 切片 | 责任边界 | 验收 |
| --- | --- | --- |
| 世界数据与迁移 | 主 AI：campaign/存档/合同地点数据 | 旧0.1.1/0.1.2档保持未结束阶段；新档保存位置、发现地点、旅行与结算键 |
| 地图 UI | 主 AI：只读世界视图和地点/路线/契约卡 | 所示口粮、天数、风险、报酬和可用性均来自规则；无伪造士气；重开无副作用 |
| 行程与内容 | 内容/战役规则：六事件地点化 | 营地接粮仓→旅行事件→原战斗→返营；六事件有稳定ID、缺席和一次/冷却测试 |
| 战斗适配 | 战斗工程：mission元数据透传 | 粮仓规则不变；胜败退都回营且不重复领奖 |
| QA与导出 | QA/主AI | 固定种子覆盖两团、两路、六事件、角色死亡、零粮零金恢复、存读档与重复结算；Windows导出走通一环 |

先做数据与迁移，再让 UI 读取，最后接旅行和结算；库存/装备随后进入营地和合同奖励，不能阻塞这个地图闭环。实施时由主 AI 确定地图阶段在 UI 层表示 `camp` 还是新增规则 phase；旅行本次沿用一次扣聚合成本的决定，内容数据不自行修改战斗核心。

六点八边的候选图容纳现有两路、猎团侦察和恢复，首个增量只开放两条已验证聚合行程，又无需生成地图、导航 AI 或多战场资产。仍待试玩决定：逐边旅行是否更易懂，低风险恢复契约是否要独立于短工，地图位置感是否足以支撑第二份合同。装备、交易、不同战场、战中事件、士气/疲劳、阵营关系与自由部署均不在本设计的实现范围。
