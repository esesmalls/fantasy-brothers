# H人物装配与动作样板

本批基于远程 `ff765de` 与 [H标准](19-art-style-standard.md)。H方向已获用户确认；A/B/C是同一方向内的材质细节和动作表现候选，仍由用户评审，不是三种新画风。当前仅一个人物身份、一个身体模板、营团剑盾、轻型衬甲与重型链甲。

**制作状态：v2技术样板已接入，待用户评审。** 首轮独立生成前臂与含上臂躯干的组合被用户退回，已从完整站姿重做无臂躯干与完整肩肘腕手臂。三套v2在引擎中复装、检查关键帧并单独导出；以下规范已据反馈修订，不以文件生成完成判定通过。见[原始反馈](../art/validation/2026-09-20-motion-templates/FEEDBACK.md)。

## 三套比较内容

| 模板 | 资产处理 | 动作处理 | 普攻 / 盾击时长 | 接触时刻 |
| --- | --- | --- | --- | --- |
| A 简练利落 | 减少碎纹理，清楚色块与外轮廓 | 小幅预备，快速出手，短停顿 | 0.42 / 0.40秒 | 总时长42% |
| B 重量明确 | 保留皮肤、衬甲和链甲磨损 | 明显蓄力、撞击停顿与回收 | 0.68 / 0.60秒 | 总时长50% |
| C 细腻舒展 | 增加克制的画笔肌理与材质变化 | 更大重心变化，更长预备与收势 | 0.92 / 0.78秒 | 总时长52% |

这些是本批可调的表现参数，不是战斗数值。三套保持同一身份、同一两甲、相同剑盾和显示尺度。静态待机、移动、挥击、盾击、防御、受击、倒下终态分别可查。倒伏终态由三套共用专用图片，不把站立纸偶旋转后当尸体。

## 文件与坐标契约

- 无损生成原件：`art/validation/2026-09-20-motion-templates/sources/`。
- 运行图集与配置：`game/assets/art/motion/`；`catalog.json`是区域、尺寸、锚点、素材与动作参数的共同入口。
- 共用绘制器：`game/presentation/modular_actor.gd`。营地肖像与战场均调用它；非样板单位、非剑盾、未支持护甲继续走原有外观。
- 生成工具：内置 image_gen；精确模型未提供，不推测。来源、提示词与哈希保存在样板目录。

三套v2原始/运行图集均为1254×1254 RGBA；两甲终态图集为1774×887。没有额外重采样的中间母版：源图原样复制到运行目录，以配置区域组织工作母版。运行时保留无损图集，通过Godot导入生成mipmap，降低小尺寸闪烁。这里不机械采用旧提案的768×704或192×176：本工程以六边格半径34逻辑像素显示人物，画布像素与战场逻辑像素是两种单位。

本次用数据记录PNG上的实际部件区域，再把它们装配到共同逻辑坐标。**不能按3×3机械等分**，生成器并未精确遵守格线。源区域允许不同，角色显示尺寸和关节语义必须一致；原PNG不因调锚点反复重采样。纹理四角变换不会覆盖战场的父级缩放。

| 部件 | 稳定ID | 对齐要求 |
| --- | --- | --- |
| 正常头 / 受击头 | `head` / `head_hit` | 同一身份，颈根共点；不得因表情替换缩头或偏脸 |
| 两甲躯干 | `armor_padded` / `armor_mail` | 相同领口、腰线、上臂连接区；读取实际装备ID |
| 主手 / 副手完整弯臂 | `right_arm` / `left_arm` | 肩端为转轴，完整肩肘腕链；另记拳内握点，躯干不能重复带上臂 |
| 单手剑 | `sword` | 握柄锚点与主手握点共用变换，出手通道避开脸 |
| 盾 | `shield` | 副手握点与盾共用变换，盾在前景遮手 |
| 低底座 | `base` | 地面原点(0,0)，不跟随呼吸旋转；下沿前景遮住腰底接缝；倒伏移除 |
| 两甲倒伏 | terminal的两甲ID | 专用整体构图、无底座、原脸原甲原剑盾 |

工作坐标：地面(0,0)，腰、颈根和双肩位置登记在catalog的anchors中。站立主体约50×70逻辑像素，挥击需要额外横向空间；不得为长剑单独缩小整个人物。具体位置须从完整结构母版测量，不把首轮退回稿的坐标视为规范。默认三分之四朝右；本批主要验收这个朝向。没有将整张角色镜像，其他朝向的专用手势和背面不属于已通过内容。

v2装配关系为：固定地面→腰→躯干/颈根/双肩→完整弯臂→握点→剑盾。躯干后领先画、头随后画、前领再盖住短颈；底座先画、下沿再盖住腰底。完整臂先画、剑随后画、拳局部最后盖住握柄，避免剑刃被上臂吞掉。各图源矩形可以不同，关节位置与显示尺度必须一致。武器不能脱离手臂做无依据的独立旋转来追目标。

## 规则与表现

战斗先计算结果，再给表现层事件。表现层通过`root_action`查询已有行动记录识别普通攻击与`shield_bash`，并核对行动者；反击不能误认成其共享根行动的移动动作。受击、数字和死亡反馈排在攻击接触点，过程中使用只读显示快照。

倍速只影响表现时钟。跳过清除待播表现并展示规则最终态，不再次扣血、费用、行动点或抽随机数。营地和战场读取同一`visual_loadout`，不靠出身锁武器。

当前规则仍是HP归零后死亡；并未实现战后重伤幸存。评审里的倒下只演示本版本终态，不新增斩首或救援结算。低HP可显示同脸痛苦表情；精细脸伤、四档甲损、永久伤残等仍须后续专用素材，不能把本批当作18计划全量完成。

## 以后如何批量生产兼容资产

1. 以选中的模板部件和完整装配画面作为参考，指定同身体模板、同光照、同朝向与同锚点。新护甲至少交躯干、必要袖件、倒伏适配；不能只有一张展示立绘。
2. 保留原图、提示词、工具输出路径和哈希。为新资产登记稳定ID、来源区域、逻辑尺寸、枢轴、前后遮挡和支持状态。不要改规则装备数值来迁就美术。
3. 在catalog中登记新ID及兼容关系。相同装配方式复用现有动作；首次增加不同握法、长枪、弓、双手武器或体型时，需要新动作家族和局部姿态，不能假定免费兼容。
4. 运行`tools/validate_motion_assets.py`检查区域、透明通道、部件缺项与共同尺寸；在实际引擎中检查站姿、蓄力、接触、收势、受击、终态，两甲和浅/深背景。
5. 用导出包实测正常尺寸、慢放、倍速、跳过和真实规则动作。通过后再扩同类外观；用户未选定模板前保留三套候选，不批量铺完整人物库。

自动检查能发现缺件、错尺寸和状态错误，不能判断是否自然、是否好看。人工重点检查颈口、肘袖、手柄、盾遮挡、腰底和最远挥击位置。样板阶段仍需要逐件校准区域；目前不能承诺“生成即入库”或固定倍数的提效。

新电脑的图集检查依赖Python 3与Pillow 12.0.0，可用 `python -m pip install -r tools/requirements-art.txt` 安装固定版本。Godot仍使用本仓库原有4.7.2；源图无需额外图像处理软件即可由配置装配。

## 评审关注点

比较正常尺寸的脸与甲是否清楚、动作是否利落、盾击是否有力量、等待时间能否接受，再看放大细节。先选一套总体偏好，也可以选择A的材质密度加B的动作节奏；资产和动作参数在配置中分别记录，可重新组合。

实际验证证据与不足见 [本批交付目录](../art/validation/2026-09-20-motion-templates/README.md)。技术通过不代表用户已批准，也不代表其他武器、体型、方向和全游戏正式美术通过。
