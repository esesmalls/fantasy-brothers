# 当前项目状态

更新：2026-09-20。最新可玩增量 **0.1.5.1：简洁战场悬浮信息**；人物培养基础为0.1.5。Godot **4.7.2 stable**，单一Windows工程，新战斗`prototype-0.1.5`。

## 用户当前方向

- 原创2D战棋与佣兵团经营，魔幻中世纪，战斗、人物故事和视觉反馈兼顾，长期目标Steam。
- 唯一真人每周10–20小时、三台电脑；主AI统筹，专项AI按重要性与成本分工。
- 先搭框架和功能，再扩内容；保留已认可的元素受击、战场优先HUD、射程与友军穿行。
- 大地图长期改为自主移动与自由探索；当前固定路线是过渡骨架，允许后置。
- 装备自由组合、穿戴可见并支持后续套层，伤势反映在脸和身体。当前只有武器/护甲两槽，未实现独立头盔、披风、副手。
- 出身、天赋与经历影响培养，每个人都能养成；永久死亡、伤残和性格变化提供需要决策的后果。
- 繁衍、童年教育与有限遗传属于长期候选；约60–80游戏日对应15年仅为待验证尺度，现在不完善系统。
- U26–U27：用户明确允许GitHub同步和接入属性培养；高出身未来承担更高招聘价格与维护费，具体数值未定。
- 最新U30：优先评审覆盖当前框架的美术制作方法，要求人物面容可区分、装备适配与套层、同装备损伤变体、战场地块叠加及完整UI美术；用户同意选型后，再展开详细方案和四步实现。
- 最新U31：用户已同意该方法，补充精细伤痕/元素/尸体、避免拼贴和马赛克阴影、大胆边框、技能/特质/性格/物品图标化与悬停详解；本轮明确要求写详细计划。
- 最新U32：倒下不一定代表死亡；胜利后倒地队员可能幸存受重伤。已并入第四步与美术状态机，具体概率和败退处理仍是待验证提案。
- 最新U33：用户要求设定集原件同步GitHub，强调正常头部/身体拆分，并先给至少4套显著不同的最小人物装备验证集，由用户评审后决定画风。本轮据此制作候选，不越过评审直接扩正式库。
- 最新U34：用户已对A/B/C/D评分4/4/2/3，要求取A清晰和伤势、B自然双手剑与死亡伤口、D表情；修缺手、武器方向、底座比例和倒姿，减少AI味，再做三套融合＋一套高度贴近Battle Brothers的精细候选。最终风格仍未定。
- 最新U35：用户明确认可E07原始成功输出的死亡伤口效果，现已恢复使用。此前淡化是主AI主动误判，不是工具拒绝；该认可不等于整套E已被选定。

## 最新交付：第二轮E–H人物装备候选

按用户上一轮评价制作E风霜纹章水粉、F铁木边民墨绘、G旅团民俗蛋彩、H精细战场兄弟半身。各套以有底座、双手完整、出手方向明确的04武装母版起步，派生换装、受伤、倒伏和独立件；增加13独立底座。[第二轮评审页](../art/validation/2026-09-20-refined-directions/index.html)可同状态对照、逐套查看、灯箱放大、128/192/256像素静态缩小及本地评分。[用户反馈](../art/validation/2026-09-20-refined-directions/FEEDBACK.md)与[实际交付/缺项](../art/validation/2026-09-20-refined-directions/README.md)分别保存。

实际交付47张PNG，共78,359,898字节；52个目标中，四套12正常身体拆件和H07死亡图被工具拦截，5项均明确标缺。E07恢复用户认可的原稿，H06追加移开枕臂、头单独落地的修正。独立元数据核对全部图片可读取、尺寸和哈希一致；评审页47图加载、缺项、灯箱、评分保存、整图缩放、窄屏及离线入口通过。生成结果不自动等于正式通过：透明边缘、画布、头身/装备锚点尚未完成校准，静态握持没有经过完整挥击/刺击动画验证。没有将空甲或模块堆当死亡稿。主AI制作H并负责集成；复用三名Sol分别完成E/F/G，并追加跨套独立视觉与元数据复核。全部使用内置image_gen，未采购服务或切到CLI/API。

第一轮A–D及原评分记录继续保留，[旧评审页](../art/validation/2026-09-19-four-directions/index.html)可回看。按用户明确要求上传的60页[设定集原件](../references/battle-brothers/README.md)仍在仓库参考目录，H重点参考其第6页模块与半身比例，不进入Godot运行资源或导出。

[18详细计划](18-art-production-plan.md)仍指导后续正式化，新增双手/武器出手通道/低底座/非睡姿倒地的检查项。下一步由用户评审E–H，再锁母版修像素装配、边缘与游戏内缩放，进入代表切片和全框架覆盖。本轮游戏、存档、战斗生死规则与导出包均未改变，可玩版仍0.1.5.1；四步功能尚未启动。

## 最近调整：0.1.5.1

- 默认角色悬浮卡使用生命/护甲/行动点色条、数值、攻击/射程/防御图标与状态/专长徽记，宽264逻辑像素；危险状态优先，溢出提示数量。物件与地表也用紧凑摘要。
- 有悬浮目标时按一次Alt展开说明，再按收起；详细宽380、正文最高300，滚轮查看完整属性、装备、效果和期限。新战斗默认简洁，弹窗期间不响应，Alt不写存档。
- 原动作预览留在底栏；鼠标移动不被卡片抢走，点击卡片区域不执行战场动作。保留战斗数值与既有元素/受击表现。
- 用户要求的下一批四步已整理为 [批次计划](16-next-four-steps.md)：招聘后勤→差异契约→出战替补部署→伤势/伤残/性格样本。可以一次交付，但按依赖串行开发验证；本轮未实现这四套新规则。

## 人物培养基础：0.1.5

1. 营地与地图营地入口新增「人物帐」：出身、经验、等级、属性来源、已学本领与履历。人物/军需两页保留同一队员互相跳转。
2. 体魄、近战技艺、远程技艺、防御实际参与战斗。来源账本统一培养、专长和装备；反复换装不重复加成，提升体魄保留伤血，甲损继续跟随实例。
3. 个人1–8级：累计每100经验升级，每级2培养点，营地自主分配。胜利存活参战者100经验，有效交战后败退35；立即逃跑、纯移动/等待/空犬指令不奖励。一次结算不能重复领取。
4. 人类基础训练花1天、1粮、1实践额度，四项可选；初始1额度，有经验的战斗补充、上限3。学习驯兽额外12金，各人类出身共享资格。
5. 长枪手等可以学驯兽、接管现有战犬，在实际战场使用标记与指令。每犬单一主人，行动次数不增加；旧岗位不再锁死人类破甲专长。犬保留经验/等级履历，但不发尚无消费用途的人类点数/额度。
6. 原战后三选一专长、死亡与装备损失、旅行—事件—契约—返营生活继续存在；元素与受击反馈保留。
7. 旧0.1.4多阶段战役自动迁移，旧专长/装备/伤血精确保留；0.1.4和0.1.1进行中战斗完整快照及RNG不变，下次出征再用新规则。

操作与数值见 [试玩说明](PLAYTEST.md)、[已实现人物规则](15-character-attributes.md)。更完整的伤残/个性/天赋方案见 [13](13-character-progression.md)，代际方向见 [14](14-family-and-legacy.md)；研究提案不等于已实现功能。

本机双击 `Play.cmd` 或 `builds/windows/FantasyBrothers.exe`。跨电脑试玩包为 `builds/FantasyBrothers-0.1.5.1-windows.zip`，不包含个人进度。建议自由团1709打一场返营分配点数；雾林猎团可直接给长枪手学习驯兽并接管战犬。

最终规则、源码UI、实际Windows导出计数及截图证据以 [08验证记录](08-validation.md)、[09视觉复核](09-visual-review.md) 为准。另两台电脑、每份真实个人旧档、长期培养经济与真人手感仍未覆盖；自动战斗结果不是玩家胜率。

## 下一候选与边界

当前仍为六地点、两条固定路线、可重复粮仓契约；三次远征的短篇收束后仍可继续。没有自由探索、丰富契约池或部署替补入口。

当前没有加入招聘阶层价格、日工资、天赋抽选、伤残性格、关系或繁衍。下一批功能最小范围及测试关卡见16，美术与四步合并实施顺序见18；方法已确认，当前交付第二轮E–H风格候选等待用户选择。详见 [框架计划](10-framework-roadmap.md)。尚无音效或已集成正式美术，装备套层仍需继续深化。
